# 외부 LLM 벤더 호출 — 금지와 그 집행 (ADR-021)

## 규칙

- **LLM 호출의 목적지는 `.env`의 `VLLM_BASE` 하나뿐이다.** KT Cloud AI Nexus vLLM
  엔드포인트다. 다른 벤더 엔드포인트로 나가는 호출은 금지다.
- 이것은 **비용 규칙이 아니라 데이터 규칙**이다. 금액이 작아도, 무료 크레딧이어도
  해소되지 않는다. 기준은 **데이터가 타사 모델로 향하는가**다.
- 벤더 SDK(`anthropic`, `openai`, `cohere`, `langchain_openai` …)를 임포트하지 않는다.
  `requirements.txt`에 넣는 것도 ADR 사안이다.

## 승인 게이트 양식 — **1번을 건너뛰지 않는다**

예외가 필요하면 아래 6항목을 **사용자에게** 제시하고 승인을 받는다.
전문은 `docs/governance.md` "승인 게이트".

1. **대상 엔드포인트가 `VLLM_BASE`인가?** — 아니오면 **승인 대상이 아니라 규칙 위반**이다
2. 나가는 데이터의 범위 (공개 / 합성 / 사내 / 고객)
3. 목적   4. 모델명   5. 건수   6. 예상 비용

> Session 0.5a에서 **2~6번은 전부 정확히 답변됐고 승인도 받았다.** 1번이 양식에 없었다.
> 그래서 규칙이 있는 상태로 위반이 게이트를 통과했다. **모델명으로 1번을 대신하지 않는다** —
> 같은 모델 이름이 우리 엔드포인트에도 벤더 엔드포인트에도 있을 수 있고,
> 판정 기준은 이름이 아니라 목적지다.

승인을 받았다면 그때 `.claude/external-llm-approved`를 만들고, 끝나면 **지운다**.
이 파일은 `.gitignore` 대상이다 — 커밋되면 1회 승인이 영구 승인이 된다.

## 집행 장치 두 개 — 무엇을 막고 무엇을 못 막나

| 계층 | 파일 | 막는 것 |
|---|---|---|
| 도구 | `.claude/hooks/check-external-llm.sh` | Bash·PowerShell **명령 문자열**의 벤더 호스트 / SDK 임포트 / API 키 주입 / 외부 모델 CLI / 생산자 파이프라인 실행 |
| 코드 | `src/providers/egress.py` + `ProviderSettings.__post_init__` | `VLLM_BASE`를 벤더로 바꿔 목적지를 돌리는 경로. **객체 생성 시점**에 실패한다 |

검사: `bash tests/gate/external_llm_cases.sh` (41건) / `pytest tests/test_external_llm_gate.py`

### ⚠️ 막지 못하는 것 — 알고 쓴다

- **스크립트 파일 경유.** `python some_script.py`의 명령줄에는 벤더 흔적이 없다.
  셸 스크립트·Makefile도 같다. **session-11에서 실제로 뚫어서 확인했다.**
- **난독화.** base64로 감싼 명령은 문자열 검사를 통과한다.
- **에이전트 자신의 모델 호출**(하네스 계층)과 Agent/Task 서브에이전트. 훅의 적용 범위 밖이다.
- **MCP 도구를 경유하는 네트워크 호출**(WebFetch 등). 매처가 `Bash|PowerShell`이다.
- **거부 목록의 빈칸.** 새 벤더·사설 프록시 호스트는 목록에 없으므로 통과한다.

이 목록은 결함 고백이 아니라 **적용 범위**다. 범위 밖을 사람이 기억으로 메우지 말고,
범위 밖에서 도는 코드(= 생산자 레포)에는 **그쪽 레포의 게이트**가 필요하다.

## 자기참조 — 오탐일 때의 정상 경로

훅은 명령 문자열을 검사하므로 **트리거 문자열이 들어간 명령은 그 자체가 차단된다.**
문서에 벤더 호스트를 예시로 적을 때가 그렇다. 회피하지 말고 **Write/Edit 도구로 파일을
쓴다.** 명령줄에 트리거를 넣지 않는 것이 우회가 아니라 정상 경로다
(`docs/governance.md`의 "검사 명령에 URL 조각을 직접 적지 않는다"와 같은 종류의 문제).
