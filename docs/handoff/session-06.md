## 이번 세션의 핵심

**컨테이너화가 보안 결정이라는 전제(session-05 §1·§2)를 검사로 증명했다.** "이미지에
안 들어간다"를 주장이 아니라 재실행 가능한 검사 결과로 남겼다.

그리고 **그 과정에서 우리 규칙을 집행하는 코드가 규칙을 만족하지 않고 있었다는 것이
드러났다.** 아래 §1이 이번 세션에서 가장 중요한 발견이다.

## 1. `redacted()`가 실제로는 가리지 않고 있었다 ⚠️

컨테이너 헬스체크를 돌리고 출력을 보다가 발견했다.

```
[INFO] 대상: {'host': 'gemma-4-31b-it-<토큰>.proxy.ainexus.ktcloud.com', ...}
```

`ProviderSettings.redacted()`는 **경로를 버리고 호스트를 남기도록** 설계돼 있었다.
governance와 README가 "진단 출력에는 이 함수를 쓴다"고 지정한 바로 그 함수다.

**그런데 실제 엔드포인트의 경로는 `/v1`뿐이다.** 가려지는 정보가 없었다. 그리고
인증이 없으므로 **호스트를 아는 것만으로 접근이 된다.** 비밀은 경로가 아니라
**호스트의 앞쪽 라벨**이었다. 즉 이 함수는 이름과 달리 아무것도 가리지 않았고,
`healthcheck.py` / `run_research.py` / `bench_golden.py` / `llm.py`의 에러 메시지가
전부 이 함수를 통해 **URL을 그대로 출력하고 있었다.**

### 고친 내용

| | 이전 | 이후 |
| --- | --- | --- |
| `host` | 전체 호스트 | `***.ktcloud.com` (공개 등록 도메인만) |
| 비교 수단 | 없음 | `endpoint_fp` = `sha256(base_url)[:12]` |

`endpoint_fp`는 **되돌릴 수 없지만 비교는 된다.** "지난 측정과 같은 엔드포인트인가"를
URL을 드러내지 않고 답한다 — 모델·엔드포인트가 바뀌면 캐시를 비워야 하므로(ADR-008)
그 판단에 쓰라고 남겼다. 테스트 2건으로 고정했다.

### 남은 조치 — 확인 필요

- ⚠️ **이 세션의 터미널 기록과 이전 세션들의 출력에 호스트가 평문으로 남아 있을 수 있다.**
  발견 전에 돌린 컨테이너 헬스체크 출력에 실제 호스트가 찍혔다. session-03~05의 실행
  로그·스크린샷을 공유한 적이 있다면 같은 노출이 있었을 가능성이 높다.
  **URL은 회수할 수 없다**(우리가 소유자가 아니다) — 확인만 가능하다.
- `var/traces/`의 기존 JSONL에 호스트가 들어갔는지는 확인하지 않았다.

> 교훈: **규칙이 있어도 그 규칙을 집행하는 코드가 규칙을 만족하는지는 따로 확인해야 한다.**
> 실제 값을 넣어 출력을 눈으로 보기 전까지 드러나지 않았다. 세션 5는 "보안 세션"이었는데도
> 이걸 못 잡았다 — 코드를 읽는 것과 돌려 보는 것이 다르다.

## 2. 컨테이너 스택 (ADR-010)

`Dockerfile`(멀티스테이지) + `docker-compose.yml` + `.dockerignore`.

**서빙은 이 스택에 없다.** 추론 엔드포인트는 KT Cloud의 관리형 vLLM이고 우리가 운영하지
않는다 (ADR-003). 올릴 수 있는 것은 오케스트레이터와 관측 백엔드뿐이며, 서빙 레그가
살아 있는지는 헬스체크가 확인한다. **"전체 스택"의 실제 범위가 이것이다.**

`orchestrator`는 **데몬이 아니라 작업 컨테이너**다 — `run --rm`으로 한 번 돌고 끝난다.
리서치 1회 = 프로세스 1회 = trace 1개라는 기존 구조를 컨테이너 경계와 일치시켰다.

### 지시받은 두 가지 — 검사 결과

| 검사 | 방법 | 결과 |
| --- | --- | --- |
| 최종 이미지 `ENV`에 시크릿 | `docker image inspect` | 비시크릿 8개만 |
| 빌드 히스토리에 URL | `docker history --no-trunc` \| `grep -F`(.env에서 읽음) | **미검출** |
| 이미지 파일시스템에 URL | 컨테이너 내 `grep -rlF /app /opt` | **미검출** |
| `.env` 존재 | 컨테이너 내 `find / -name .env` | **없음** |
| `/app/var/*` | 컨테이너 내 `ls -laR` | **비어 있음** (마운트 지점만) |

검사 명령에 URL 조각을 적지 않고 `.env` 값을 읽어 대조했다 (governance의 커밋 전 확인과 같은 방식).

`var/`는 named volume 3개(`traces` / `llm_cache` / `chroma`)로 뺐다. **이미지에 굽지 않는
이유는 용량이 아니라 내용이다** — 이미지 배포가 곧 프롬프트·응답 배포가 된다.

### 실측

| 항목 | 결과 |
| --- | --- |
| 이미지 크기 | **3.46GB** (torch CPU + 가중치 470MB) |
| 컨테이너 테스트 | **114 passed** (네트워크 없이) |
| 헬스체크 | OK, 0.66~0.92s |
| 인덱싱 | 16건 / **10.5s** (호스트 19.9s — 가중치가 로컬이라 HF 조회가 없다) |
| e2e (GS-001) | 13콜 / 34.86s / 출처 표기 유지 |

베이스는 **Python 3.14 유지**. 로컬과 런타임이 갈라지면 측정치를 비교할 수 없다.
`torch 2.9.0`의 cp314 리눅스 휠이 존재하는 것을 확인하고 CPU 인덱스에서 설치했다
(기본 PyPI는 CUDA를 통째로 끌고 온다).

## 3. Langfuse self-host — ADR-007의 미검증 경로 해소 (선택 항목, 완료)

`--profile langfuse`로 v3 스택(web/worker + PostgreSQL + ClickHouse + Redis + MinIO,
컨테이너 6개)을 띄우고 **실제 전송을 확인했다.**

| 항목 | 결과 |
| --- | --- |
| 서버 | `{"status":"OK","version":"3.225.7"}` |
| 수신 | `research_run` trace 1건 / observation **19개** |
| 내역 | GENERATION 13 (outliner 1 · researcher 5 · verifier 6 · writer 1) + SPAN 6 |
| 충실도 | `model=gemma-4-31B-it`, `usage={input:1131, output:247, total:1378}`, `latency=4.462` |
| 터미널 요약과 대조 | 13콜 / 12875+881 토큰 — **일치** |

README §5.5의 한계 항목을 해소로 표시했다. **다만 §4의 수치 자체는 여전히 로컬 JSONL
기준이다** — 재측정이 아니라 전송 경로를 검증한 것이다.

### 막힌 곳 두 개 (해결됨, 기록용)

1. **MinIO가 Docker Hub에서 내려갔다.** `minio/minio` pull 실패 → `quay.io/minio/minio`가
   공식 배포처다. compose에 주석으로 남겼다.
2. **`LANGFUSE_INIT_USER_EMAIL=dev@localhost`가 거부된다.** zod 검증이 TLD를 요구한다.
   마이그레이션(424건)까지 다 돈 뒤 web만 기동 실패해서 원인이 안 보였다 —
   `docker compose logs langfuse` 앞부분에 `❌ Invalid environment variables`가 있다.

### 남은 것

- Langfuse SDK가 `Context error: No active span in current context`를 출력한다.
  **데이터는 전부 도착했지만** 스팬 중첩이 SDK v4의 기대와 완전히 맞지는 않는다.
  표시 문제로 보이나 **확인되지 않았다.**
- compose의 Langfuse 자격증명은 **전부 로컬 개발용 기본값**이다 (`pk-lf-local-dev`,
  `ENCRYPTION_KEY`가 0으로 채워진 값 등). 평문으로 적혀 있고 **의도된 것이다.**
  ⚠️ **이 값이 배포로 넘어가면 사고다.**

## 4. 임베딩 가중치 리비전 고정 (ADR-011)

session-05가 "셋 중 가장 싼 개선"으로 지목한 항목이다.

- `infra/model-pin.json` — repo_id / revision / allow_patterns / 파일 sha256
- `scripts/fetch_model.py` — 고정 다운로드 + sha256 검증. **불일치는 경고가 아니라 실패다.**
- Dockerfile builder 스테이지에서 빌드 시 검증 → `/opt/models`에 굽고
  런타임은 `EMBEDDING_LOCAL_PATH` + `HF_HUB_OFFLINE=1`

**리비전과 sha256은 대체 관계가 아니다.** 리비전은 "무엇을 받을지"를, sha256은 "받은 것이
맞는지"를 고정한다.

### 고정 대상이 "지금 쓰고 있는 그것"임을 확인했다

| | 값 |
| --- | --- |
| HuggingFace API `sha` (HEAD) | `614241f622f53c4eeff9890bdc4f31cfecc418b3` |
| 로컬 HF 캐시 `refs/main` | **동일** |
| `model.safetensors` sha256 (로컬 ↔ API) | **일치** (`1a55775f53449dac…`) |

→ session-03에서 인덱스를 만든 리비전과 같다. **이 고정은 기존 측정치를 바꾸지 않고
인덱스 재생성도 필요 없다.** ADR-005 Amendment의 수치(재현율 71.4% / 간격 0.074)가 그대로 유효하다.

`EMBEDDING_MODEL`을 다른 모델로 바꾸면 **매니페스트의 리비전을 물려주지 않는다** —
엉뚱한 해시로 다른 가중치를 받는 것을 막기 위함이다. 그 경우 `EMBEDDING_REVISION`을
직접 넣어야 하며, 안 넣으면 고정이 풀린 채로 돈다 (`pinned`가 False).

### 한계

- **sha256 보증은 LFS 파일 3개뿐이다.** HuggingFace API가 작은 JSON 설정 파일에는
  sha256을 주지 않는다. `1_Pooling/config.json`이 바뀌면 풀링이 달라지는데 리비전 고정으로만
  보증된다.
- **공급망 셋 중 하나만 닫았다.** **의존성 해시 미고정**과 **엔드포인트 모델 지문 확인
  수단 없음**은 그대로 열려 있다 (owasp-notes §3.1).

## 5. ADR-005 Review Trigger 응답 — Chroma 유지 (ADR-012)

**지시대로 검색 품질 문제와 섞지 않았다.** 판단 기준은 컨테이너화/운영 편의성뿐이다.

| 기준 | 판단 |
| --- | --- |
| 스케일 | 코퍼스 16건, 컬렉션 1개, 동시 질의 0 — Qdrant의 강점이 값을 하지 않는다 |
| 영속성 | named volume 하나로 해결됐다. 서버형도 결국 볼륨 하나를 붙이는 건 같다 |
| 백업 | **재생성이 10.5초다.** 백업 대상 자체가 아니다. 서버형은 오히려 스냅샷 API 절차가 늘어난다 |

**ADR에 명시했다: Qdrant로 옮겨도 GS-006은 여전히 실패하고 간격은 여전히 0.074다.**
두 저장소 모두 **우리가 계산한 같은 벡터를 같은 코사인 거리로 정렬한다.** ADR-005가 애초에
벡터 DB 선택과 임베딩 선택을 묶지 않도록 설계했기 때문에(Chroma 기본 임베딩 함수를 쓰지
않는다) 한쪽을 바꿔도 다른 쪽은 변하지 않는다. 저장소는 그 문제와 무관하다.

**전환 조건(Review Trigger):** 오케스트레이터 복제본이 **2개 이상**이 되어 같은 인덱스를
공유해야 하는 경우(임베디드의 단일 프로세스 전제가 깨진다), 또는 코퍼스가 수천 건 규모가
되는 경우. ⚠️ **복제본 2개는 배포 설정 변경으로 조용히 일어날 수 있다** — 자동 감지 수단이 없다.

## 6. 배포 대상 — ECS Fargate 온디맨드 태스크 (ADR-013)

**Bedrock은 후보에서 제외**했다 (파운데이션 모델 서빙이라 ADR-003과 겹치고 컨테이너 배포와 무관).

### 유휴 시 고정비 (list price)

| 후보 | 유휴 월 고정비 | 근거 |
| --- | ---: | --- |
| **ECS Fargate (온디맨드)** | **~$0.35** | 컨트롤플레인 무료, 태스크 미실행 시 컴퓨트 0. ECR 저장 3.46GB만 |
| App Runner | ~$10+ | 서비스가 사는 동안 프로비저닝 메모리 과금 |
| EKS | **~$73** | 컨트롤플레인 $0.10/h × 730h. 노드 별도 |

실행 1회는 약 **$0.017** (2vCPU/4GB, 10분 가정). **월 100회를 돌려도 ~$1.7**이다.
→ 이 워크로드에서 비용을 지배하는 것은 실행량이 아니라 **켜 두는 것** 자체다.
EKS 고정비가 실행 비용의 40배가 된다.

### App Runner는 비용보다 구조가 먼저 걸린다

App Runner는 **HTTP 요청을 받는 서비스**를 전제한다. 우리 오케스트레이터는 CLI 배치라
포트를 열지 않는다. 올리려면 **쓰지도 않을 웹 API를 감싸야 하고, 그러면 배포한 것이
검증한 스택과 달라진다.**

### 포트폴리오 가치

ECS Fargate가 중간이면서 정직하다 — 태스크 정의·IAM 역할 분리·VPC·ECR·CloudWatch가
전부 드러난다. App Runner는 감춰서 보여줄 게 없고, **EKS는 더 보여주지만 이 워크로드에
k8s가 필요했다는 근거가 없다** — 과잉 설계는 가산점이 아니라 판단력에 대한 감점이다.

⚠️ 비용 수치는 list price 추정이다. apply 전에 갱신해야 한다 (결정을 뒤집을 크기는 아니다).

## 7. Terraform 최소 구성 (`infra/terraform/`) — **apply 안 함**

리소스 **2개**뿐이다. 둘 다 ECS의 선행 리소스이면서 유휴 비용이 사실상 0이다.

- `aws_ecr_repository` (+ 수명주기 정책 — 이미지 3.46GB가 쌓이는 것이 유휴 고정비를
  만드는 **유일한 경로**라 필수다)
- `aws_cloudwatch_log_group`

**클러스터·태스크 정의·IAM 역할은 일부러 넣지 않았다.** `var/`를 클라우드에서 어디에 둘지가
미정인데, 지금 태스크 정의를 쓰면 **감사 로그가 사라지는 구성**을 코드로 굳히게 된다
(Fargate 로컬 스토리지는 태스크 종료와 함께 사라진다).

`./apply.sh`가 게이트를 강제한다 — `plan`/`validate` 등 읽기 동작은 통과시키고
`apply`/`destroy`만 `.claude/deploy-approved` 확인. **동작 확인함**(승인 파일 없는 상태에서
`apply` 차단됨). `-auto-approve`를 기본으로 두지 않았다 — 게이트를 하나 줄이는 셈이라서다.
삭제 절차는 `infra/terraform/README.md`에 있다 (ECR은 이미지가 남아 있으면 destroy가 실패한다 —
`force_delete`를 켜지 않은 것은 의도다).

`terraform`·`aws` CLI가 이 머신에 설치돼 있지 않아 **`terraform validate`를 돌리지 못했다.**
문법은 검토했지만 **검증되지 않은 상태다.**

## 8. `var/` 보존·접근 기준 확정 (governance.md)

세션 5부터 빈칸이던 값을 채웠다.

> **커밋되지 않는 로컬 개발 편의용 파일 — 필요 없어지면 수동 삭제, 별도 접근 통제 없음
> (로컬 파일시스템 권한 따름).**

명시한 것 두 가지:

- ⚠️ **이 기준은 ADR-004("공개 arXiv 초록만")에 의존한다.** 실데이터가 들어오는 순간
  **즉시 무효**이며, 보존 기간·접근 주체·삭제 책임자를 정하는 것이 그 투입의 선행 조건이다.
- ⚠️ **로컬/개발 환경 한정이다.** 클라우드에 올리면 "로컬 파일시스템 권한"으로 보호되지
  않는다 — **배포 전에 다시 정해야 한다.**

## 다음 세션(실제 배포) 사전 준비 — 사용자가 해야 할 것

### A. 계정 · 자격증명 (없으면 apply 불가)

1. **AWS 계정** — 결제 수단이 등록돼 있어야 한다. 프리티어 여부와 무관하게 ECR 저장·
   CloudWatch는 과금 대상이다.
2. **IAM 사용자 또는 역할 + 로컬 자격증명 구성**
   - `aws configure` 또는 `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_DEFAULT_REGION`
   - **루트 계정 키를 쓰지 않는다.**
   - 필요 권한(이번 세션 범위): `ecr:*`(리포지토리 생성·수명주기·푸시),
     `logs:*`(로그 그룹 생성·태그), `iam:*`은 **세션 7 후반**(태스크 역할 만들 때) 필요.
   - MFA를 쓴다면 세션 토큰 발급 절차를 미리 확인해 둘 것.
3. **AWS CLI v2 설치** — 현재 이 머신에 **없다**. ECR 로그인·이미지 푸시·삭제 절차에 필요하다.
4. **Terraform 설치** (`~> 1.9`) — 현재 이 머신에 **없다**. 이것 때문에 `validate`도 못 돌렸다.
5. **`.claude/deploy-approved` 파일** — `touch .claude/deploy-approved`.
   **승인을 주기로 결정한 뒤에** 만든다. 이 파일은 승인 그 자체가 아니라 기록이다.

### B. 결정해야 할 것 (apply 전에)

6. **리전 확정** — 기본값을 `ap-northeast-2`(서울)로 뒀다. 추론 엔드포인트가 AWS 밖 한국에
   있고 파이프라인 1회에 10~13콜이 오가므로 지연 때문이다. 비용은 `us-east-1`이 약간 싸다.
7. **`var/`를 클라우드에서 어디에 둘 것인가 (EFS vs S3)** — **가장 중요한 선행 결정.**
   정하지 않고 태스크 정의를 쓰면 감사 로그가 태스크 종료와 함께 사라진다 (ADR-007 요구 미충족).
   그리고 정하는 순간 **보존 기간·접근 주체를 다시 정해야 한다** — 로컬 기준(§8)이 적용되지 않는다.
8. **Langfuse를 클라우드에도 올릴 것인가** — 올린다면 컨테이너 6개가 **상시 실행**이므로
   "유휴 고정비 0"이 깨진다. 그리고 compose의 로컬 개발용 자격증명을 **전부 새로 발급**해야 한다.
   (개인적으로는 로컬에만 두는 쪽을 권한다 — 배포 목적이 오케스트레이터 실행이라면.)

### C. 확인만 필요 (막지는 않음)

9. **사내 보안 정책상 무인증 엔드포인트 사용이 허용되는가** — session-03부터 열려 있다.
   배포가 답을 바꾸지는 않지만 **노출 지점이 하나 늘어난다.**
10. **비용 수치 갱신** — ADR-013의 표는 list price 추정이다.

## 주의 (이월 + 갱신)

- 코드 실행은 **레포 루트를 cwd로**.
- 지연 측정 전 **`LLM_CACHE` 상태 확인**, **임베딩 콜드 로딩 분리** (governance "측정 방법론").
  컨테이너에서는 가중치가 로컬이라 콜드 로딩이 19.9s → 10.5s로 줄었다 — **호스트 수치와
  직접 비교하지 말 것.**
- 인덱스·트레이스·캐시는 커밋하지 않는다. **컨테이너에서는 named volume에 있다** —
  이미지를 지워도 남고, `docker compose down -v`로 지운다.
- 임베딩 모델을 바꾸면 `python scripts/build_index.py --reset` **+ `EMBEDDING_REVISION` 설정**
  (안 하면 고정이 풀린다).
- **모델이 바뀌면 캐시를 비울 것.** 이제 `endpoint_fp`로 엔드포인트 변경을 확인할 수 있다.
- **Python 3.14 + Pydantic V1:** 컨테이너도 3.14다(의도적). 노드에서 pydantic 모델을 쓰기
  시작하면 터질 수 있다 — 그때 컨테이너 베이스를 3.12/3.13으로 내릴지 재검토 (ADR-010 Review Trigger).
- **새 의존성 없음.** `huggingface_hub`은 sentence-transformers의 기존 전이 의존성이다.

## 승인 게이트

`docs/governance.md`대로 진행했다. **승인이 필요한 일은 없었다.**

- 엔드포인트 호출(헬스체크 3회 + e2e 3회)은 **기존 무료 할당 자원**이라 사전 승인 불필요.
- 컨테이너·Langfuse는 **로컬**이다. 새 유료 리소스 0개.
- **`terraform apply`를 실행하지 않았다.** 코드만 준비했고 게이트가 차단하는 것을 확인했다.
- 새 의존성 없음, 되돌리기 어려운 외부 상태 없음.
- **커밋 전 시크릿 검사 실행함** (governance의 명령 그대로) — 출력 비어 있음.
