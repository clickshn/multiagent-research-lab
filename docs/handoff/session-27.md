### 1.1 GS-027 — 왜 깨졌나

- #0 항목 "LLM 에이전트 기반 공장 설비 제어 사례"에서 `Agent` 선택 → 무필터 2~4위(`news:42f467…`·`news:c076df…`·`news:0252e9…`, 셋 다 새 라벨에 `Agent` 없음)가 지워지고
  `arXiv:2405.16887v2`(층 B GS-003 정답, 새 라벨 `Agent`)가 3위로 올라와 인용됐다.
- **N1과 같은 문서·같은 항목·같은 값.** N1에서는 메타가 없어서, v1.2.1에서는 감사상 **맞는** `Agent` 라벨로 생존했다 → 라벨 정확도 문제가 아니다.
- `news:0252e9…`는 Opus 라벨에 `Agent`가 있었고 gemma가 뺐다(감사 안 함). 이 탈락이 정답을 4위 → 3위로 올렸지만 N1에서 4위로도 인용됐으므로 필요조건은 아니다.
- 인용된 항목 자체는 그 문서 초록(물리 shopfloor 실험)이 뒷받침한다. 깨진 것은 질의 수준 negative("안전 사고")다. 골든셋 rationale이 처음부터 "이 문서가 강하게 끌린다"고 적은 근접 negative다.

## 2. 감사 결과와 해석 — "필터 효과" 대 "라벨 정확도"

**감사는 Claude(Claude Code)의 독립 감사다. 사람이 하지 않았다.** 규칙(R1~R7)을 판정 전에 적었다(사전 등록 §1.1).

| 항목 | 결과 |
|---|---|
| `Agent` 정확도 | **11/14** (틀림 0 · 애매 3: #7 HumanEvalComm · #11 GS-006 · #14 GS-003) |
| 정답 문서 10건 중 `Agent` 맞음 | **8/10** (애매 2) |

| 보충(층 A 앵커 4건 바뀐 값) | 새로 붙은 값 3건 틀림(`Inference/Serving` · `Data/Synthetic` · `Reasoning`), GS-018 앵커는 `Multimodal`·`Data/Synthetic`이 빠짐 |

**감사 결과 대비 해석:**

- 층 B 회복(T3a 0/9 → 7/9)은 **라벨 커버리지 효과**다. 층 B 선택값은 32/32가 새 라벨과 호환이었다 — 정답 문서 10건 전부 `Agent`가 붙었기 때문이다.
  감사상 그중 2건(GS-006 · GS-003의 2406.01893)의 `Agent`는 애매다. 즉 **층 B 회복의 일부는 감사상 확정되지 않은 라벨 위에 있다.** 다만 해악 항목 0이라 라벨이 틀렸어도 결과가 바뀌는 경로(L−·L+)는 이번에 발동하지 않았다.
- 해석 규칙(§8) 분류: **L− 0 · S 0 · U 0 · L+ 0**(층 A·B). 선택된 값 중 감사상 틀린 라벨로만 생존한 항목이 없다.
- 층 C 해악은 해악 항목 없이 생긴 뒤집힘 → 규칙대로 **필터가 후보 풀을 바꾼 효과**로 적었다. 라벨 정확도로 귀속하지 않는다.
- **결론:** v1.2.1의 해악은 라벨 정확도가 아니라 **필터 효과**다. 라벨이 정확해져도(또는 정확해서) 재현된다.
  `release_type` 정확도는 낮지만(8/14) 이 측정의 판정 경로 밖이다(출처 표 표시에만 나타난다).
- ADR-029 원인 진술(D4 = 메타 부재)은 확인됐고, ADR-030/README의 "근본 원인은 메타 없는 14건"은 D5에 대해서는 틀렸다 → 정정(ADR-030 Amendment, README §4.9).
