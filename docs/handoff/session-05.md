## 1. GS-006 크로스링구얼 진단 — 가설 기각 (수정 없음)

**지시받은 대로 코드·모델을 건드리지 않고 진단만 했다.** 결과는 ADR-005 Amendment.

### 먼저 정정할 사실 두 가지

1. **실패한 골든셋 케이스는 GS-006 **1건뿐**이다** (`bench-no-cache.json` → `scoring.failed = 1`).
   "나머지 실패 케이스들"은 없다. n=1이라 실패군/통과군 비율 비교가 성립하지 않는다.
2. **크로스링구얼 비율은 실패군·통과군 모두 100%다.** 골든셋 9건이 전부 한국어 질의이고
   코퍼스 16건은 **한글이 한 글자도 없는 영어 문서**다(전수 확인). 크로스링구얼은
   **변수가 아니라 상수**이므로 이 값으로는 아무것도 설명할 수 없다. 동일 언어 대조군이 0건.

### 그래서 대조군을 만들어 쟀다

같은 질의의 **영어 번역**을 같은 인덱스에 넣어 기대 문서 순위를 비교했다
(읽기 전용 프로브, 레포 코드 수정 없음, LLM 엔드포인트 호출 없음).

| 지표 (positive 7건) | 한국어 질의 | 영어 질의 |
| --- | ---: | ---: |
| top-4 재현율 | 5/7 = **71.4%** | 6/7 = **85.7%** |
| 기대 문서 평균 순위 | 3.29 | 2.29 |

**(a) 크로스링구얼이 재현율을 깎는 것은 사실이다** — GS-007이 5위 → 1위로 올라온다.
**(b) 그러나 GS-006은 설명되지 않는다** — 영어 질의에서도 16건 중 **8위**다.
**유일한 실패 케이스가 유일하게 번역으로 고쳐지지 않는 케이스다.**

### 더 그럴듯한 원인 — 임베딩 변별력 부족

| 관측 | 값 |
| --- | ---: |
| 한국어 질의, 1위와 4위의 점수 차 | 0.009 ~ 0.013 |
| 코퍼스에 답이 **전혀 없는** 질의(GS-008)의 최고 점수 | 0.766 |
| 정답을 1위로 맞힌 질의(GS-005)의 최고 점수 | 0.840 |
| **"완전 무관"과 "정답"의 간격** | **0.074** |

모든 문서가 모든 질의에 비슷하게 유사하다. top-4 절단이 의미 차이가 아니라 노이즈로
결정된다. **이 수치는 보안 항목이기도 하다** — 인덱스 오염 난이도가 이 간격에 비례한다.

**후속(범위 밖):** 임베딩 모델을 바꾸기 전에 **골든셋에 영어 질의 대조군부터 넣어야 한다.**
지금 구조로는 언어 효과를 영원히 측정할 수 없다.

## 2. `var/llm_cache/` 거버넌스

- **gitignore:** 이미 `var/`로 덮여 있었다 — 다만 그건 **Python 표준 템플릿의 distutils용
  항목**이라 "우리가 정해서 제외한다"는 의도가 남지 않는다. 명시적 블록을 추가했다
  (`var/llm_cache/`, `var/traces/`, `var/chroma/` + 왜 제외하는지 주석).
- **`docs/governance.md`에 "로컬 산출물 취급" 절 신설** — `var/llm_cache/`는 `var/traces/`와
  **동일한 보존기간·접근권한 기준**을 따른다. **평문 응답이 로컬에 쌓인다는 사실을 문서화**했다.
  ⚠️ 다만 **기준값 자체가 아직 미정**이다(traces 쪽도 미정) — "동일 기준"도 현재는 빈 값이다.
- **`docs/governance.md`에 "측정 방법론" 절 신설** — 지연·비용 측정 전 `LLM_CACHE` 상태 확인.
  (`.env`에 `LLM_CACHE`가 없어 현재 기본 꺼짐 상태임을 확인했다.)

## 3. OWASP LLM Top 10 정리 — `docs/security/owasp-notes.md`

Top 10을 요약하고 우리 파이프라인의 해당 지점을 매핑했다. 해당 없는 항목도 **왜 없는지**
적었다 — 구조가 바뀌면 그 전제가 먼저 깨지기 때문이다.

**먼저 용어를 정정했다.** 이 프로젝트는 "폐쇄망"이 아니다(세션 2에 정정됨). 실제 제약은
**외부 LLM 벤더 비의존**이다. 이 차이가 위협 모델을 바꾼다 — 망 분리에서 오는 보호를
하나도 못 받으면서, 외부 벤더의 안전장치는 제약 때문에 못 쓴다. **보호 장치는 전부 자체 구현.**

**특히 위험한 3개:**

1. **LLM03 Supply Chain** — 임베딩 가중치·의존성 해시 미고정. **엔드포인트 자체가 공급망**
   인데 우리가 운영하지 않아, 같은 이름으로 다른 모델이 재배포돼도 탐지 수단이 없다.
2. **LLM08 Vector/Embedding Weaknesses** — 추측이 아니라 이번에 실측됐다(위 §1, 간격 0.074).
   정상 문서 간 점수 차가 0.01이면 **조금만 더 유사한 문서 하나로 top-k를 뺏을 수 있다.**
3. **LLM01 Prompt Injection (간접)** — 외부 가드레일을 못 쓰는 제약이 정확히 여기서 비용이 된다.

**인프라 수준 리스크(§4)를 별도 소항목으로 뒀다** — 애플리케이션 계층에서 고칠 수 없는
것을 위 3개와 섞지 않기 위해서다. 무인증 엔드포인트가 여기 들어간다. IP 화이트리스트·
API 키·네트워크 분리 **전부 불가**(우리는 소유자가 아니다), 가능한 건 URL을 시크릿으로
다루는 것 하나뿐. **기술 과제가 아니라 조직의 정책 확인 과제다.**

완화 사실도 함께 적었다: **ADR-004로 실데이터 투입을 범위 밖에 뒀기 때문에** 지금 사고가
아니다. **해결이 아니라 회피이고 유효기간이 있다** — 실데이터 투입 결정과 위 정책 확인은
**같은 게이트에 묶여야 한다.** 순서가 뒤집히면 되돌릴 수 없다.

## 4·5. 인젝션 케이스 10건 + 방어 적용

케이스 정의는 `tests/security/injection_cases.py` **한 곳**에 두고, 테스트와 측정
스크립트가 같은 정의를 쓴다(따로 들면 방어 전/후가 서로 다른 공격을 가리키게 된다).

**"방어 전"을 상상해서 적지 않았다.** `UNTRUSTED_DATA_RULE`을 시스템 프롬프트에서 실제로
잘라내고 본문도 경계 없이 결합한 session-04 구성을 만들어 **같은 모델에 실제로 보냈다.**
판정은 전부 결정적인 문자열·JSON 검사다(LLM 심판을 쓰면 모델 고정 원칙과 충돌).

### 적용한 방어 (ADR-009)

| 계층 | 방어 | 성격 |
| --- | --- | --- |
| 툴 ingress | `ToolScope` — 출처 화이트리스트 + `k`·질의 길이 상한, 위반 시 **예외** | 결정적 |
| 툴 egress | 스코프 밖 `source`를 결과에서 제외 | 결정적 |
| 프롬프트 | `wrap_untrusted` 신뢰 경계 + 구분자 위조 무력화 | 결정적(경계 위조 한정) |
| 프롬프트 | `UNTRUSTED_DATA_RULE` 지시 | **완화 — 보장 아님** |
| 관측 | `detect_injection` 패턴 플래그 | **탐지 전용, 차단 아님** |

- 스코프 강제는 **`build_graph()` 한 곳**에서 한다 — 호출부가 빠뜨릴 경로를 없앴다.
- 위반이 **빈 결과가 아니라 예외**인 이유: 둘이 같은 신호를 내면 로그로 공격을 볼 수 없다.
- 본문은 **삭제하지 않는다** — 코퍼스에 *AgentHarm* / *AgentLAB* 처럼 공격 기법을 정상
  서술하는 논문이 실재해서, 패턴 삭제는 정상 문서를 먼저 망가뜨린다.
- `PROMPT_VERSION` `2026-09-15.1` → `2026-09-16.1`.

## 6. 못 막은 것 · 증명하지 못한 것 (README §7에 그대로 남김)

숫자만 보면 "10/10 차단"이지만 **그렇게 읽으면 안 된다.**

1. **모델 의존 6건 중 5건은 방어 전에도 안 뚫렸다.** 이 5건에 대해 우리 방어는 **무엇도
   증명하지 못했다.** 정확히는 **1건을 막았고 5건은 원래 안 뚫렸다.** INJ-03/05/07은
   방어 전후 출력이 **바이트 단위로 동일**했다.
2. **INJ-07은 케이스 설계가 약했다** — 근거 주제가 너무 동떨어져 인젝션과 무관하게
   `uncovered`가 나왔다. 인젝션이 아니라 주제 불일치를 잰 것이다. **재설계 대상.**
3. **탐지 패턴이 자기 페이로드 3건(INJ-03/07/08)을 놓쳤다.** 직접 쓴 목록으로 직접 쓴
   공격을 못 맞혔다. 그래서 탐지는 **관측 전용**이다. 알려진 우회 3종은 테스트에서
   **고의로 통과시켜** 한계를 고정해 뒀다.
4. **표본 1회** (`temperature=0`, 조건당 1콜). "안 뚫림"은 이 모델·프롬프트·페이로드 한정.
5. **시도하지 않은 것:** 난독화(Base64·유니코드), 분산 인젝션, 재검색 2회차 경로,
   **실제 인덱스 오염**. 마지막은 §1의 간격 0.074를 보면 **성공 가능성이 높다고 본다**(추정).

**유일하게 실제 피해였던 케이스(INJ-08)**는 문서가 Writer에게 출처 표기를 떼게 만든 것이다.
방어 전 출력에서 `[arXiv:2405.16887v2]`가 사라지고 "모든 근거 검증됨"이 삽입됐다.
**출처 추적성이 이 프로젝트의 1순위 목표**라 가장 아픈 지점이었고, 방어 후 유지된다.

## 다음 세션(컨테이너화 / IaC) 전에 알아야 할 것

1. **`var/`를 컨테이너에서 어디에 둘지가 보안 결정이다.** `var/llm_cache/`와 `var/traces/`에
   **프롬프트와 응답 본문이 평문으로** 쌓인다. 이미지 레이어에 들어가면 이미지를 받는
   모두가 읽는다. **볼륨으로 빼고, 이미지에 포함되지 않는지 확인할 것.**
2. **`VLLM_BASE`가 이미지 레이어에 박히지 않게 할 것.** URL이 곧 접근 권한이다
   (`docs/governance.md`). 빌드 인자·`ENV`·복사된 `.env` 어디에도 들어가면 안 되고,
   **레이어는 지워도 히스토리에 남는다.** 런타임 주입만 허용.
3. **`.claude/rules/iac.md`와 governance의 IaC 게이트를 먼저 읽을 것.** `terraform apply`
   류는 사용자 승인 + `.claude/deploy-approved` 파일 존재 확인이 **둘 다** 필요하다.
   세션 7의 클라우드 배포는 **새 유료 리소스**라 사전 승인 대상이다.
4. **ADR-005 Review Trigger가 이번 세션(6)을 지목하고 있다** — Chroma → Qdrant 이전 여부를
   별도 ADR로 판단할 시점이다. 다만 §1에서 드러난 문제는 **저장소가 아니라 임베딩 모델**
   쪽이므로, 저장소를 바꿔도 재현율은 안 변한다는 점을 섞지 말 것.
5. **ADR-009 Review Trigger:** 컨테이너화 시점에 `var/` 배치와 URL 노출을 확인하도록
   이미 걸어 뒀다.
6. **임베딩 모델을 컨테이너에 어떻게 넣을지가 공급망 항목이다** (owasp-notes §3.1).
   런타임에 HuggingFace에서 받으면 재현성과 공급망이 둘 다 깨진다. **해시 고정 + 이미지에
   포함**이 지금으로선 가장 싼 개선이다.
7. **컨테이너 안에서 `python -m pytest tests/security/ -q`가 통과해야 한다** — 네트워크 없이
   도는 42건이라 이미지 스모크 테스트로 쓰기 좋다.

## 주의 (이월, 여전히 유효)

- 코드 실행은 **레포 루트를 cwd로**.
- 지연 측정 시 **임베딩 콜드 로딩(19~30s)을 분리**할 것. 그리고 측정 전 **`LLM_CACHE`
  상태 확인** (governance "측정 방법론").
- 인덱스·트레이스·캐시는 커밋하지 않는다. 재현 기준은 `data/corpus/` 스냅샷 + 임베딩 모델 이름.
- 임베딩 모델을 바꾸면 `python scripts/build_index.py --reset`.
- **모델이 바뀌면 캐시를 비울 것** — 같은 이름으로 재배포되면 캐시 키가 못 잡는다.
- **Python 3.14 + Pydantic V1:** langfuse가 먼저 깨질 가능성이 높다. 이번 세션에도
  **새 의존성을 설치하지 않았다** (스코프·sanitize 모듈은 표준 라이브러리만 사용).

## 승인 게이트

`docs/governance.md`의 규칙대로 진행했다. 승인이 필요한 일은 없었다.

- 엔드포인트 호출(인젝션 프로브 12콜)은 **기존 무료 할당 자원**이라 사전 승인 불필요.
- 크로스링구얼 프로브는 **로컬 임베딩·로컬 인덱스만** 사용(엔드포인트 호출 0).
- 새 의존성 없음, 새 유료 리소스 없음, 되돌리기 어려운 외부 상태 없음.
- **커밋 전 시크릿 검사 실행함** (governance의 명령 그대로) — 출력 비어 있음.
