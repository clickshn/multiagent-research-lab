## 1. 무슨 일이 있었나 — 한 문단

Session 0.5a에서 계약 검증용 추출을 **외부 Anthropic API(`claude-opus-5`)로 실행했다.**
이 프로젝트의 전제는 외부 LLM 벤더 비의존이다. 승인 게이트는 **목적·모델명·건수·

`VLLM_BASE`인가"는 아무도 묻지 않았다.**

> **게이트가 있었고 통과했는데, 게이트가 확인해야 할 것을 확인하지 않았다.**
> 양식이 묻는 것은 전부 비용의 크기였다. **비용 게이트가 규칙 자리에 놓인 채 정상
> 작동했고, 그래서 실패 신호가 하나도 나지 않았다.**

## 3. 🚩 뚫어 봤다 — 막은 것과 못 막은 것

**만든 것과 작동하는 것은 다르다.** 세션 안에서 실제로 시도했다.

| 시도 | 결과 |
|---|---|
| Bash 도구로 벤더 호스트가 든 명령 | **차단(exit 2)** |
| **PowerShell 도구**로 같은 시도 (session-07의 우회 경로) | **차단(exit 2)** |
| `VLLM_BASE`를 벤더로 교체 후 설정 로딩 | **차단** (`ExternalEndpointError`) |
| jq·python을 모두 감춘 환경 | **차단** (fail-closed) |
| 승인 파일이 있을 때 / 지운 뒤 | 통과 → 다시 차단 |
| **스크립트 파일 안에 벤더 호출을 숨기고 `python <파일>`** | ⚠️ **통과했다 — 막지 못한다** |

또한 `settings.json` 변경이 **재시작 없이 이번 세션에서 바로 유효**했다.

### ⚠️ 막지 못하는 것 — 기억이 아니라 테스트에 적혀 있다

케이스 파일에 **기대값 0(통과)** 으로 5건 고정했다. 인젝션 테스트에서 탐지 우회 3종을
고의로 통과시켜 한계를 고정한 것과 같은 방식이다.

- **스크립트 파일 / 셸 스크립트 / Makefile 경유** — 명령줄에 벤더 흔적이 없다
- **난독화**(base64 등) — 문자열 검사를 통과한다
- **에이전트 자신의 모델 호출과 Agent/Task 서브에이전트** — 훅의 적용 범위 밖
- **MCP 도구 경유 네트워크 호출** — 매처가 `Bash|PowerShell`이다
- **거부 목록의 빈칸** — 새 벤더·사설 프록시는 목록에 없다

> 이 목록은 결함 고백이 아니라 **적용 범위**다. 범위 밖에서 도는 코드가 바로
> 생산자 레포이고, 그래서 §5가 **다음 세션의 첫 과제**다.

### 5.1 왜 vLLM 이전보다 먼저인가

> ⚠️ **MARA의 훅은 MARA 세션에서만 돈다.** 생산자 레포에는 이 게이트가 없다.
> **지금 생산자 세션을 열면 같은 위반이 그대로 가능하다.**

순서를 뒤집으면 안 되는 이유가 하나 더 있다. **vLLM 이전 작업 자체가 그 레포에서 LLM을
호출하는 일이다.** 30건 재추출·judge 재측정이 전부 LLM 호출이고, 설정을 잘못 두거나
기본값이 남아 있으면 **그 호출이 벤더로 나간다.** 장치 없이 시작하면 §1과 같은 일이
**전제를 고치러 가는 작업 중에** 다시 난다.

**게이트 이식은 vLLM 이전의 선행 조건이지 병행 작업이 아니다.**

### 5.2 이식할 것

1. **PreToolUse 훅** — `.claude/hooks/check-external-llm.sh`를 그 레포에 맞춰 옮긴다.
   매처는 `Bash|PowerShell`, 차단은 exit 2, **파서가 없으면 통과가 아니라 차단**(fail-closed),
   예외는 1회용 승인 파일(`.gitignore` 대상).
2. **코드 계층 불변식 — (가) 기본 차단 + 승인 파일 경유로 간다. 결정 완료.**
   MARA의 `ProviderSettings.__post_init__`에 해당하는 자리는 생산자의
   `extraction/llm.py`(Protocol 구현체 생성 지점)와 `config.yaml` 로딩 지점이다.

   **왜 (가)인가 — 상태를 정확히 표현하는 것이 (가)뿐이다.**
   생산자의 벤더 호출은 ADR-021 이후로 **"정상 경로"가 아니다.** **이전이 끝날 때까지
   승인받고 쓰는 예외 경로**다. 기본 차단 + 1회용 승인 파일이 정확히 그 상태다 —
   기본값은 금지이고, 예외는 매번 사람이 열고 닫는다.

   ⛔ **(나) 경고·기록만 두는 안은 기각한다. 이번 사고의 원인을 그대로 반복한다.**
   0.5a의 게이트도 **있었고 통과했다.** 실패는 "장치가 없었다"가 아니라 **"장치가
   확인할 것을 묻지 않았다"**였다. 경고는 답을 요구하지 않는 장치이므로, 같은 계열의
   실패를 한 번 더 만든다 — 로그에 남아도 아무도 멈추지 않으면 그건 게이트가 아니다.

   **부수 효과 — 이게 (가)를 고르는 두 번째 이유다.**
   승인 파일 없이 파이프라인을 **한 번 돌리면 벤더를 부르는 지점이 전부 드러난다.**
   지금 우리가 아는 것은 추출·관련성 게이트 **둘**이지만, 그건 `config.yaml`을 읽어서
   안 것이지 실행해서 확인한 것이 아니다. **실측 목록이 있어야 vLLM 이전 범위를 정할 수
   있다** — 목록을 추정으로 만들면 이전하고 나서 "여기도 있었네"가 나온다.
   그래서 아래 5번에 **"차단 상태 1회 실행"을 검사 항목으로 넣는다.**
3. **게이트 양식 6항목** — 생산자 `docs/governance.md`와 `CLAUDE.md`에. 1번이
   "대상 엔드포인트가 `VLLM_BASE`인가"이고 **아니오는 승인 대상이 아니라 규칙 위반**이다.
   ADR에만 적지 않는다 — MARA에서 세 곳에 적은 것과 같은 이유다.
4. **한계도 그대로 이식한다.** `python <파일>` 우회·셸 스크립트·Makefile·난독화는
   **저쪽에서도 못 막는다.** 산문으로 적지 말고 **케이스 파일에 기대값 0(통과)으로**
   넣는다. 막지 못하는 범위가 테스트에 있어야 다음 사람이 "이건 막히겠지"로 넘어가지 않는다.
5. **뚫어보기 재실행.** MARA에서 통과했다고 저쪽에서 통과하는 것이 아니다 —
   경로·PATH·실행기(`.venv`/`uv`)·파서 후보가 다르다. 최소한 이 다섯은 다시 돌린다:
   Bash 도구 / **PowerShell 도구** / 환경변수 교체 / 파서 부재(fail-closed) /
   스크립트 파일 경유(**통과해야 정상** — 한계 고정).

   ➕ **이식 직후 "차단 상태 1회 실행"을 검사 항목으로 넣는다.**
   승인 파일이 **없는 상태로** 파이프라인을 한 번 돌리고, **어디서 멈추는지를 전부
   기록한다.** 이것이 벤더 호출 지점의 **실측 목록**이고, §6의 이전 범위를 정하는 근거다.
   - 기대: 첫 벤더 호출 지점에서 예외로 멈춘다. **통과해서 끝까지 돌면 이식이 실패한 것이다.**
   - 한 번 멈추고 끝내지 말고, **드러난 지점을 임시로 우회하며 끝까지 훑어** 목록을 닫는다
     (예: 그 단계를 건너뛰고 다음 단계로). 한 번에 한 지점씩만 보이므로 반복이 필요하다.
   - 결과는 "추출 / 관련성 게이트 / judge / 그 밖에 발견된 것"으로 적는다.
     **지금 아는 둘은 `config.yaml`을 읽어서 안 것이지 실행해서 확인한 것이 아니다.**
   - ⚠️ 이 실행에서 **외부 API 호출은 0건이어야 한다.** 차단이 목적이므로 나가면 안 된다 —
     나갔다면 그것 자체가 이식 실패의 증거이고, 그 사실을 기록한다.
6. **ADR 남기기.** 생산자 ADR은 016까지 있으므로 **ADR-017**이 된다. MARA의 ADR-021을
   가리키고, 두 레포의 규칙이 같은 것임을 양쪽에서 확인할 수 있게 한다.

### 5.3 이식은 복사가 아니다 — 오탐 대조를 새로 짜야 한다

- **생산자에는 `anthropic` SDK가 실제로 설치돼 있다**(`.venv`). MARA에서는 "SDK 임포트"가
  곧 위반 신호였지만, 저쪽에는 **SDK를 임포트하는 정상 코드와 테스트가 있다.**
  같은 패턴이 정탐이자 오탐이 되므로 **오탐 대조 케이스를 그 레포 기준으로 새로 만든다.**
- MARA의 훅에 있는 `PRODUCER_RUN`(생산자 파이프라인 실행 차단)은 **저쪽에서는 의미가
  뒤집힌다** — 그 레포에서 그 명령은 정상 작업이다. 그대로 복사하면 자기 파이프라인을
  자기가 막는다.
- 파서 탐색 순서(`python` 우선)와 **"있는지가 아니라 도는지"** 검사는 그대로 가져간다.
  이건 환경 문제라 레포와 무관하게 똑같이 밟는다.

### 5.4 이 세션의 조건

- **외부 API 호출 0건.** 이식 세션에서는 LLM을 부르지 않는다.
- MARA 쪽은 건드리지 않는다. 이번 세션과 반대 방향의 경계다.

## 6. 그다음 — 추출 단계를 KT Cloud vLLM으로 이전

**§5가 끝난 뒤에 시작한다.** 목적은 비용 절감이 아니라 전제 위반 해소다.
ADR-002가 서빙을 vLLM(`gemma-4-31B-it`)로 정했는데 **코퍼스 생성만 외부 벤더를 쓰고 있다.**

- **대조 설계:** 이미 Opus 5로 뽑은 **30건과 동일한 입력**을 vLLM으로 다시 돌린다.
  생산자 보존소에 원문이 남아 있어 수집을 다시 하지 않으므로 **추가 비용 0**이고,
  "같은 입력 · 다른 모델"의 단일 변수 비교가 된다.
- **판정 기준은 데이터를 보기 전에 등록했다** →
  **`docs/eval/preregistration-extraction-on-vllm.md`** (session-11 커밋 `615d0bf`).
  요약: **① 통제어휘 이탈률 ≤ 5% 그리고 ② structured output 실패율 ≤ 10%** 이면 합격.
  ③ judge 점수 차이(≤ 0.5)는 기록하되 단독으로 불합격을 만들지 않는다.
- ⚠️ **judge도 vLLM으로 바꿔야 한다.** 생산자 `config.yaml`의 `eval.judge_model`이
  `claude-opus-5`다 — **판정하는 행위 자체가 같은 위반이 된다.**
- ⚠️ 대조 성립 조건 4가지(프롬프트 무변경 / structured output 강제 수준 / 재시도 정책 /
  `prompt_sha256`)를 **먼저 확인하고 결과를 적는다.** 여기서 갈리면 대조를 시작하지 않는다.
- **이전 범위는 추정하지 말고 §5.2-5의 실측 목록으로 정한다.** 승인 파일 없이 한 번
  돌려서 드러난 "벤더를 부르는 지점" 전부가 범위다. 지금 아는 둘(추출·관련성 게이트)에
  `eval.judge_model`을 더해 셋이지만, **그건 설정 파일을 읽어서 안 것이지 실행해서 확인한
  것이 아니다.**
- ⚠️ **이 작업이 끝나도 §5가 필요 없어지지 않는다.** 프로바이더를 바꿔도 `anthropic`
  SDK는 그 레포에 설치돼 있고, 설정 한 줄로 되돌아간다. 장치가 남아야 한다.
