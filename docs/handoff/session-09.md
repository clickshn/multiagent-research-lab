## 1. 이번 세션의 핵심

**두 레포를 잇는 방법을 고르는 문제가 아니라, "무엇을 인용 근거로 삼을 것인가"를
고르는 문제였다.**

`ai-news-ontology`의 Obsidian 노트에는 **원문 본문이 없다.** 노트에 실리는 텍스트는
Opus 5가 쓴 한국어 요약 2~3문장뿐이다. 그래서 "Vault를 읽을 것인가 export를 만들 것인가"는
경로 선택이 아니라 **인용이 원문을 가리킬 것인가 모델 패러프레이즈를 가리킬 것인가**의
문제였고, 이 프로젝트의 1순위 지표(인용 정확도)가 답을 정했다.

이 프로젝트가 반복해 온 패턴이 여기서도 한 번 더 보인다 — **규칙을 세운 쪽과 그 규칙이
실제로 적용된 쪽이 다르다.** 생산자 레포의 `SourceRef`/`NewsNote` 모델에는 `published_at`·
`collected_at`이 정의돼 있지만, **실제 Obsidian 출력 경로는 그 모델을 쓰지 않는다**
(extractor는 `NewsOntology`를, writer는 `NewsOntology + NoteContext(RawItem)`를 다룬다).
스키마에 있다고 출력에 있는 것이 아니다 — 계약을 문서가 아니라 **파일 형식**으로 못박은
이유가 이것이다.

## 2. 확정된 계약 (v1.0)

전문은 `docs/contracts/ai-news-ontology-export-v1.md`. 확정 사항만 옮긴다.

### 2.1 전송 형식

| | |
|---|---|
| 형식 | JSONL (레코드 1건 = 1줄) + `.manifest.json` |
| 경로 | `data/corpus/news/<export_id>.jsonl`, `data/corpus/arxiv/<export_id>.jsonl` |
| `export_id` | `ontology-YYYYMMDD-HHMMSS` (생산자 export 실행 시각, KST) |
| 커밋 | **한다.** 재현 기준은 인덱스가 아니라 스냅샷이다 (ADR-004) |

### 2.2 확정된 필드 (전부 필수)

**최상위 17개**

`contract_version` · `doc_id` · `source` · `source_name` · `url` · `title` · `lang` ·
`text` · `text_origin` · `text_chars` · `text_truncated` · `locator` · `published_at` ·
`collected_at` · `ontology` · `provenance` · `indexable`

**`ontology` 7개** — 5필드 + 파생 텍스트 2개

`tech_domains`(닫힘 14, 1~3) · `release_type`(닫힘 8, 정확히 1) ·
`companies[]{canonical, raw, resolved, role}` · `prior_art`(열림 0~8) ·
`impact_score`(1~5) · `impact_rationale` · `summary`

**`provenance` 7개** — 5개는 누락 시 import 실패

`extraction_model` · `prompt_version` · `prompt_sha256` · `extracted_at` ·
`vocab_version` (필수) / `gate_model` · `gate_prompt_version` (null 허용)

### 2.3 계약의 핵심 규칙 5가지

1. **`doc_id`는 결정적으로 생성한다.** URL 정규화(추적 파라미터 제거·쿼리 정렬·프래그먼트
   제거·끝 슬래시 제거) 후 `news:<sha256(canonical_url)[:16]>`.
   **arXiv는 `arXiv:<id><version>`으로 MARA 기존 표기와 바이트 단위 동일하게** —
   두 레포가 같은 논문을 수집하므로 중복을 "탐지"하지 않고 **같은 키로 겹치게** 만든다.
2. **원문 텍스트만 색인한다.** `summary`·`impact_rationale`은 메타데이터로만 싣고
   색인·인용 경로에 넣지 않는다. `text_origin`은 v1에서 `"source_text"` 한 값만 유효.
3. **통제어휘는 생산자가 정본.** MARA는 복제하지 않고 manifest 스냅샷과 대조만 한다.
   값 **추가**는 통과, **삭제·개명·쪼개짐**은 import 실패.
4. **`provenance` 누락은 실패.** 코퍼스가 외부 모델 버전의 함수라는 사실을 기록으로
   남기지 않으면 ADR-002(모델 고정)가 코퍼스 쪽에서 조용히 깨진다.
5. **MARA는 `indexable`을 재계산해 대조한다.** 생산자 계산값을 그대로 믿으면 두 레포의
   규칙이 갈렸을 때 알 수 없다.
6. **`text` 길이 상한 4,000자를 계약 상수로 박았다** (§6.1). 생산자의 `BODY_MAX_CHARS`를
   참조하는 것이 아니라 **복사해 고정**한다. 목적은 생산자의 D-013(원문 페이지 fetch)이
   나중에 실행돼도 **계약을 재협상하지 않게** 하는 것이다 — 상한과 `text_truncated`가
   형식 변화를 흡수한다. ⚠️ **흡수되는 것은 형식뿐이고, "전문을 반입해도 되는가"는
   ADR-004 재검토 사안으로 그대로 남는다.**

### 2.4 온톨로지 5필드의 소비 등급

| 필드 | v1 처리 | 이유 |
|---|---|---|
| `release_type` | 메타데이터 + **필터 후보 1순위** (배선은 **Session 3**) | 닫힘 8·정확히 1이라 등치 필터로 깨끗하고, `Paper`(근거급) 대 `Community/Discussion`(의견)을 가르는 축이라 인용 품질에 직결 |
| `tech_domains` | 메타데이터만 | 골든셋 9건이 전부 멀티에이전트/에이전트 주제 → `Agent`/`Eval`로 수렴, 100건 규모에서 선택도 없음 |
| `companies` | 메타데이터만 | 정밀도는 최고지만 **현 골든셋에 기업명이 하나도 없다** — 수요 0 |
| `prior_art` | 키워드 확장 전용 | 사전 없는 열린 어휘. 열거할 수 없는 값으로는 필터를 만들 수 없다 |
| `impact_score` | 정렬·리포팅 전용 | `impact>=4` 필터 = **모델 주관 점수로 근거를 버리는 것** |

> ⚠️ **값 분포는 미측정이다 — 위 등급은 실측이 아니라 예측이다.** 생산자 레포에 대량
> 실행 산출물이 없고(`observability/logs/` 부재) 확정 골든셋은 3건이다. 판단 근거는
> **구조적 카디널리티(닫힘/열림, 값 개수, 단일/다중) + 코퍼스 성격**뿐이다.
> **확정은 첫 export의 manifest `counts`로 한다**(계약 §8.1). 판정 임계값(상위 1개 값
> 80% 초과 → 필터 후보에서 제외 등)은 **데이터를 보기 전에 계약에 사전 등록해 두었다** —
> 분포를 본 뒤에 기준을 정하면 어떤 결과에도 해석을 붙일 수 있기 때문이다.

## 3. Session 0.5 범위 결정 — **양쪽 구현까지**

계약이 실제로 흐르는지 e2e로 확인하고 닫는다. 검색 품질 개선은 범위 밖이다.

### 들어가는 것

| # | 작업 | 레포 |
|---|---|---|
| 1 | export 스크립트 — `RawItem` + `NewsOntology` + 실행 메타 → JSONL + manifest | ai-news-ontology |
| 2 | `doc_id` 생성(URL 정규화 + arXiv 특례) — **양쪽에 같은 규칙으로**, 동일 입력·동일 출력 테스트 | 양쪽 |
| 3 | `.jsonl` 로더 + 온톨로지 메타데이터 적재 (`CorpusDoc.as_metadata()`가 현재 스칼라 6키만 싣고 `extra`를 버린다) | MARA |
| 4 | import 검증 **7종** + `indexable` 재계산 대조 (`text` 4,000자 상한 검증 포함) | MARA |
| 5 | 첫 export manifest 분포로 §2.4 예측 검증 — **판정 임계값은 계약 §8.1에 사전 등록돼 있다** | MARA |

**MARA 쪽 경계: 스키마·로더 확장까지다.** 온톨로지 필드를 `CorpusDoc` 메타데이터로
**싣기만 하고** 검색 경로(`src/tools/retrieval.py`)는 건드리지 않는다.

### 들어가지 않는 것

| 항목 | 언제 | 왜 지금이 아닌가 |
|---|---|---|
| **`release_type` 필터 배선** (`src/tools/retrieval.py:171-183`) | **Session 3** | 0.5에서 배선하면 **코퍼스가 10배가 되는 변경과 검색 조건이 바뀌는 변경이 한 세션에 겹친다.** 수치가 움직여도 어느 쪽 때문인지 가를 수 없어 Session 3의 "하나만 바꾸고 대조"가 성립하지 않는다 (ADR-002와 같은 논리) |
| 골든셋 개정 | v1.1 본세션 | 코퍼스가 늘면 `expected_doc_ids`를 다시 확인해야 한다(골든셋 파일 자신의 주의사항). **새 문서가 더 좋은 근거이면 기존 기대값이 틀린 것이 된다** |
| 크로스링구얼 대조군 설계 | v1.1 본세션 | 한국어 문서가 들어오는 것과 그것으로 실험을 설계하는 것은 다른 일이다 (session-08 §7 (다)) |
| `tech_domains`/`companies` 필터 배선, 질의 재작성, 임베딩 모델 교체 | 미정 | 배선 여부 자체가 §2.4 예측 검증 결과에 달려 있다 |
| `MIN_TEXT_CHARS` 실제 값 | Session 0.5 이후 | 분포를 본 뒤 측정으로 정한다 (v1은 1 = 비어 있지 않음) |

## 4. 코퍼스 초기 규모

**현재: arXiv 16건 (arXiv 429로 session-03 이후 증가 없음, `news` 출처 0건)**

생산자 실측(D-013/D-014, 소스당 50건 표본)으로 역산한 1차 export 퍼널:

| 단계 | 건수 | 근거 |
|---|---:|---|
| 원시 수집 (5소스 × 최근 50건) | ~250 | 생산자 `config.yaml` 소스 5개 |
| 관련성 게이트 통과 | ~230 | GeekNews 약 60%만 AI 관련(D-014), 나머지 소스는 대부분 통과 |
| 본문 0자 제외 | ~165 | HF Blog 50/50 제외, DeepMind 15/50 제외 |
| └ `arxiv` 출처로 분리 | ~50 | `doc_id` 규칙으로 기존 16건과 병합·중복 제거 |
| └ **`news` 출처 색인 가능분** | **~115** | |

- **1차 목표: `news` 출처 색인 가능 100건.** 미달하면 GeekNews 수집 범위를 넓힌다
  (한국어 소스라 크로스링구얼 쪽 이득도 같이 늘어난다).
- 합치면 MARA 코퍼스는 **16건 → 대략 150~180건**. 규모 자체보다 **출처가 2종이 되고
  한국어가 처음 들어온다**는 것이 중요하다.
### 4.1 비용과 승인 게이트 — **2단계로 쪼갠다**

게이트+추출은 외부 벤더 API다. 생산자 실측 **100건당 약 $2.92**로 250건이면 약 $7이고,
MARA의 무료 할당 자원(`VLLM_BASE`) 밖이라 **governance 승인 게이트 대상**이다.
한 번에 승인받지 않고 나눈다.

| 단계 | 규모 | 비용 | 목적 | 실행 조건 |
|---|---:|---:|---|---|
| **1단계** | 30건 | **≈ $0.9** | **계약 e2e 검증 전용** — 코퍼스 확보가 아니다 | 사용자 승인 |
| **2단계** | 220건 | **≈ $6.4** | 코퍼스 확보 | **1단계 체크리스트 13항목 전부 통과 후에만** |

**쪼개는 이유는 금액이 아니라 실패 시 손실의 크기다.** 스키마·형식 결함은 표본 수에
비례해 드러나지 않는다 — 30건에서 안 걸리는 형식 결함은 250건에서도 대체로 안 걸리고,
반대로 **250건을 다 쓴 뒤 스키마 문제를 발견하면 같은 돈을 두 번 낸다.**

### 4.2 1단계 표본 30건 — **arXiv 중복 케이스 2건을 명시적으로 넣는다**

| 건수 | 대상 | 검증 대상 |
|---:|---|---|
| **2** | `arXiv:2412.05449v1`(GS-001 기대값), `arXiv:2605.21404v1` | `doc_id` 동일화·병합 + **골든셋 기대값 보존** |
| 8 | arXiv cs.CL 피드 신규 | 긴 본문·`locator="abstract"` 경로 |
| 10 | GeekNews | 한국어·`text_truncated=true` 경로 |
| 5 | OpenAI News / DeepMind Blog | 짧은 본문(97~149자) |
| 5 | Hugging Face Blog | 본문 0자 → `indexable=false` 제외 경로 |

⚠️ **중복 2건은 피드에 우연히 섞이길 기대할 수 없다.** 생산자는 arXiv **최근** 피드를
읽고 MARA의 16건은 **주제 질의 결과**라 겹칠 이유가 구조적으로 없다. URL을 직접
입력해야 하므로 **export 스크립트의 `--urls` 입력이 1단계 구현 항목**이다.
이게 없으면 `doc_id` 동일화는 **검증되지 않은 채 통과한 것처럼 보인다.**

### 4.3 통과 기준 (요약) — 전문은 계약 §12.2

**13항목 전부 통과해야 2단계로 넘어간다.** 하나라도 실패하면 고치고 1단계를 다시 돈다.

1. e2e 완주(JSONL 30줄 + manifest, 로더 적재까지 예외 없음)
2. `provenance` 5키 — 30줄 **전부** 존재, 빈 문자열 아님
3. `prompt_sha256`이 실제 프롬프트 파일 해시와 일치(자리표시자 아님)
4. `text_origin` 30줄 전부 `"source_text"`
5. **arXiv 중복 2건이 새 `doc_id`를 만들지 않는다** — arXiv 문서 수 = `16 + 신규 건수`
6. 골든셋 `expected_doc_ids` **한 건도 안 깨짐**
7. `doc_id` 결정성 — 2회 export 결과가 바이트 동일
8. `len(text) <= 4000` 이고 `text_chars == len(text)`
9. `indexable` 재계산 일치 (HF Blog 5건이 `false`)
10. 통제어휘 대조 — 모든 값이 manifest `vocab` 안
11. `published_at` 누락이 빈 문자열이 아니라 `null`
12. manifest 합계 — `total == 30`, `indexable + excluded_empty_text == 30`
13. 한국어 레코드가 실제로 인덱스에 들어가고 `lang="ko"`로 조회됨

**1단계 실패 시 비용을 두 번 내지 않으려면** 추출 결과 원본을 로컬에 보존해야 한다
(계약 §12.3). 생산자는 `NewsOntology`를 Obsidian 노트 외에 보존하지 않아서, 보존하지
않으면 **형식만 틀렸는데 LLM을 다시 부르게 된다.**

## 5. session-08 미해결 항목 중 **경로가 생긴 것**

| 항목 (session-08 §7) | 이번 결정의 효과 |
|---|---|
| **골든셋 영어 질의 대조군 / "크로스링구얼이 변수가 아니라 상수"** | GeekNews(한국어 소스)가 코퍼스에 들어오면 상수가 변수가 된다. **경로가 생겼을 뿐 실험 설계는 아직 없다** |
| **arXiv 429 → 코퍼스 16건, `news` 출처 공백** | ADR-004가 열어 두고 채우지 못한 `news` 슬롯이 채워진다. arXiv도 다른 수집 경로가 하나 늘어난다(같은 IP·같은 제한이므로 **보장은 아니다**) |
| `min_citations` / `top_k`가 근거 없는 출발점 | 직접 해소되지 않는다. 다만 `MIN_TEXT_CHARS`를 같은 방식으로 만들지 않기로 했다 — `text_chars`를 전 레코드에 실어 분포부터 본다 |

**여전히 안 풀린 것:** 무인증 엔드포인트 사용 허용 여부, 2026년 말 대체 서빙 경로,
`var/` 삭제 책임자, 관리형 정책 1개(`AWSBudgetsActionsWithAWSResourceControlAccess`)
루트 콘솔 detach. 전부 조직 결정이거나 콘솔 작업이다.

## 6. 결정 대기 / 다음 세션이 먼저 답해야 할 것

| 항목 | 왜 지금 못 정했나 |
|---|---|
| **`MIN_TEXT_CHARS` 값** | 뉴스 본문 중앙값이 97~160자라 임계값을 올리면 뉴스가 대부분 빠지고, 안 올리면 160자짜리가 인용 근거가 된다. **분포를 보기 전에 정하면 근거 없는 손잡이가 하나 더 생긴다** |
| **`text_truncated=true`인 문서를 근거로 인정할 것인가** | GeekNews 40/50건이 말줄임 절단이다. 잘린 문장을 인용하면 근거가 문장 중간에서 끝난다. 계약은 플래그만 싣고 판단은 남겼다 |
| **골든셋 개정 시점과 주체** | 코퍼스가 10배가 되면 `expected_doc_ids`가 틀릴 수 있다. 개정 없이 벤치를 돌리면 **숫자가 나빠진 것인지 기대값이 낡은 것인지 구분할 수 없다** |
| **생산자 레포의 본문 fetch(D-013) 도입 여부** | 도입되면 피드 발췌가 아니라 기사 전문이 반입된다 → **저작권 판단 + ADR-004 재검토 사안.** 생산자 레포의 결정이지만 MARA 쪽 전제를 바꾼다 |

## 7. ADR-004 부합 여부 — **부합한다 (단서 3개)**

`src/tools/corpus.py: ALLOWED_SOURCES = ("arxiv", "news")`의 **`news` 슬롯이 정확히 비어
있고**, ADR-004 Implementation의 유일한 미완 체크박스가 `[ ] news 출처 수집`이다.
생산자의 코퍼스는 공개 RSS/Atom(arXiv, 벤더 블로그, GeekNews)이므로 **범위 확대가 아니라
이미 승인된 범위의 미집행분 집행**이다.

단서:

1. **파생 텍스트.** ADR-004는 합성 문서를 "출처가 지어낸 것이면 측정에 의미가 없다"로
   기각했다. `summary`/`impact_rationale`은 지어낸 것은 아니지만 모델 출력이다 →
   **계약 §6에서 색인·인용 금지로 못박았다.**
2. **arXiv 중복** → **계약 §4.3의 `doc_id` 동일화로 구조적으로 해소.**
3. **본문 fetch** → 계약 §10에서 범위 밖으로 명시. 실행되면 ADR-004 재검토.

추가로, 데이터가 외부 벤더(Anthropic)로 나가는 것은 **생산자 레포에서 이미 일어나는
일**이고 대상은 공개 자료뿐이라 MARA의 "외부 LLM 벤더 비의존" 제약 자체는 깨지지 않는다.
다만 **코퍼스가 외부 모델 버전의 함수가 된다**는 새로운 사실이 생겼고, 이것은 ADR-004가
아니라 **ADR-002(모델 고정)** 쪽 문제다 → `provenance` 필수화로 대응했다.
