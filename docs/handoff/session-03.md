# Session 03 핸드오프 — Sub-agent 구현 + 검색 계층 + 계측 + e2e 성공

- **날짜:** 2026-09-15
- **범위:** 코퍼스 범위 확정(공개 자료 한정), VectorDB·임베딩 확정, 네 노드 내부 로직 구현,
  Langfuse 계측, e2e 실행 성공, 골든셋 초안
- **신규 ADR:** ADR-004 / ADR-005 / ADR-006 / ADR-007. ADR-002에 Amendment 추가.

## 이번 세션의 핵심 변화

**파이프라인이 실제로 돈다.** session-02에서 배선만 있던 그래프에 네 노드의 내부 로직이
들어갔고, 실제 엔드포인트 + 실제 Chroma 인덱스로 **e2e 실행 2회가 성공했다.**
session-02에서 "막힌 것"으로 기록됐던 **VectorDB 선택과 골든셋이 둘 다 풀렸다.**

**"근거 없으면 문장을 만들지 않는다"가 구조로 지켜지는 것이 확인됐다.** 코퍼스에 근거가
전혀 없는 질의(한국 개인정보보호법)를 넣었을 때, 모델이 알고 있을 법한 주제인데도 네 항목
전부 "근거 없음"만 남기고 한 문장도 지어내지 않았다. 상세는 `docs/eval/run-log-session-03.md`.

## 완료된 것

### A. 결정 (ADR 4건 신규 + 1건 보강)

| ADR | 결정 | 핵심 근거 |
| --- | --- | --- |
| **ADR-004** | 샘플 코퍼스는 **공개 자료로만** 구성. 사내 기밀 문서는 넣지 않는다 | 엔드포인트가 무인증 공개 접근이라 사내 문서 투입은 회사 보안 정책 검토가 별도로 필요한 문제이고, 이 포트폴리오 프로젝트의 범위 밖 |
| **ADR-005** | VectorDB는 **Chroma 임베디드**, 임베딩은 **로컬 `multilingual-e5-small`** | 엔드포인트 `/v1/embeddings`가 **404**(실측). Chroma는 서버 없이 이번 세션에 붙는다. 세션 6에서 Qdrant 이전 여부 재검토 |
| **ADR-006** | Verifier 되돌림 조건 = **기계 판정 + 모델 판정 2단계**, 판정 실패는 통과시키지 않음 | 셀 수 있는 것(인용 수)을 모델에 묻지 않는다. 검증 실패를 통과로 처리하면 검증 단계가 있으나 마나 |
| **ADR-007** | 계측은 **Tracer 파사드** 뒤에. 로컬 JSONL 기본 + Langfuse 옵션 | 감사 로그가 인프라 구성 여부에 좌우되면 안 된다. SDK 메이저 버전 변경이 노드 수정으로 번지지 않게 |
| **ADR-002 Amendment** | "폐쇄망 반입 절차 전제"의 적용 범위 명시 | 개발 환경은 인터넷 접근 가능하고 PyPI에서 직접 설치한다. 반입 절차 전제는 프로덕션 폐쇄망 배포 시나리오에 대한 것 |

### B. 코드

- `src/tools/corpus.py` — 코퍼스 반입 정책. `ALLOWED_SOURCES = ("arxiv", "news")`를
  **코드에 박고** 인덱싱·검색 경로가 강제한다. 목록 밖 출처는 빈 결과가 아니라 예외다.
- `src/tools/retrieval.py` — Chroma 검색 툴. 결과에 `doc_id`·`locator`가 항상 실린다.
  임베딩 모델 이름을 컬렉션 메타데이터에 남겨 **모델 불일치를 에러로 잡는다**
  (조용한 품질 저하 방지).
- `src/providers/embeddings.py` — `EmbeddingProvider` 프로토콜 + sentence-transformers 구현.
  e5 접두사(`query: `/`passage: `)를 설정으로 들고 다니고, 비-e5 모델이면 자동으로 끈다.
- `src/providers/config.py` — `EmbeddingSettings` / `VectorStoreSettings` / `TracingSettings` 추가.
  환경변수를 읽는 유일한 지점이라는 규칙 유지.
- `src/obs/` — Tracer 파사드. 실행 1건 = trace 1개, 모델 호출 1건 = span 1개.
  `CompositeTracer`로 로컬 JSONL은 항상, Langfuse는 구성됐을 때만.
- `src/orchestrator/nodes.py` — **네 노드 전부 구현.** 모델 호출이 전부 `_call()` 한 곳을
  지나므로 "모든 호출이 기록된다"가 구조로 보장된다.
- `src/orchestrator/prompts.py` — 프롬프트 분리 + `PROMPT_VERSION`. 재현성 요구가
  프롬프트 버전을 파이프라인 구성의 일부로 보기 때문이다.
- `scripts/` — `probe_embeddings.py`(엔드포인트 임베딩 지원 확인), `ingest_corpus.py`(공개
  코퍼스 수집, 재개 가능), `build_index.py`, `run_research.py`(단계별 계측 요약 출력).
- **테스트 67개 통과** (session-02의 5개 → 67개). 기존 5개는 그대로 통과 — 노드 팩토리
  시그니처를 하위 호환으로 유지했다.

### C. 실측

**엔드포인트 임베딩 지원** (`scripts/probe_embeddings.py`로 재현 가능):

| 요청 | 결과 |
| --- | --- |
| `GET /v1/models` | HTTP 200 — `gemma-4-31B-it` 단일 모델 |
| `POST /v1/embeddings` | **HTTP 404** `{"detail":"Not Found"}` |

**e2e 실행 2회** (상세는 `docs/eval/run-log-session-03.md`):

코퍼스 16건 인덱스 기준:

| 실행 | 질의 성격 | 호출 | 입력/출력 토큰 | LLM 지연 합 | 벽시계 |
| --- | --- | ---: | ---: | ---: | ---: |
| `20260915-152557-c34630` | 근거 있음 | 14 | 11,717 / 1,581 | 29.26s | 55.60s |
| `20260915-152711-81bcd7` | 근거 없음(GS-008) | 10 | 10,820 / 241 | 5.76s | 33.93s |

근거 없는 질의에서 **Verifier 호출이 0회**다 — 인용이 0개인 항목은 모델을 부르지 않고
기계 판정으로 걸러지기 때문이다 (ADR-006). 그만큼(3,336 토큰 / 8.62s) 아꼈다.

### D. 골든셋 초안 — session-02의 "막힌 것" 해소

`docs/eval/golden-set.json` (정본) + `docs/eval/golden-set.md` (방법론). **9건**:
근거 있음 7건 + **음성 케이스 2건**.

기대 기준은 e2e 출력이 아니라 **코퍼스 원문(초록)을 직접 읽고** 작성했다. 시스템 출력을
정답으로 삼으면 자기 자신을 기준으로 채점하게 되기 때문이다.

음성 케이스 2건이 가장 중요하다 — GS-008은 사전 지식으로 지어내는지, GS-009는 검색이
"비슷해 보이는" 문서를 물어오고 Verifier가 통과시키는지를 본다.

## 열린 이슈 / 결정 대기

### 막힌 것

- **arXiv가 이 IP를 429로 막고 있다.** 코퍼스 수집 5개 주제 중 **2개만 성공**해서
  인덱스가 **16건뿐이다.** 20초 간격 + 최대 80초 백오프로도 풀리지 않았고, 세션 종료
  시점에도 여전히 429다. `scripts/ingest_corpus.py`는 **재개 가능하게** 만들어뒀으니
  (이미 받은 주제는 건너뛴다) 다음 세션에서 그냥 다시 돌리면 남은 3개를 이어서 받는다.
  **코퍼스가 작아서 "근거 없음"이 실제보다 많이 나올 수 있다** — 실행 1의 근거 없음 2건이
  시스템 결함인지 코퍼스 부족인지는 코퍼스를 더 늘린 뒤에야 갈린다.
- **`news` 출처가 비어 있다.** 화이트리스트에는 열어뒀지만 수집하지 않았다. 출처가
  하나뿐이라 출처 다양성에서 오는 문제가 아직 드러나지 않는다.

### 새로 드러난 것

- **재검색 루프의 기대 효과가 낮다.** 네 번의 실행 모두 재검색 2회를 돌았지만 근거를 새로
  찾은 항목이 **0건**이다. 같은 인덱스에 거의 같은 검색어를 다시 던지기 때문이다.
  **검색어를 실제로 바꾸는 단계(질의 재작성)가 없다는 것이 구조적 한계**이고,
  현재 형태의 재검색은 비용만 늘릴 가능성이 있다 (ADR-006 Risks). 코퍼스를 늘린 뒤에도
  같은 양상이면 루프 설계를 다시 봐야 한다.
- **벽시계 시간의 절반 이상이 LLM 밖에 있다.** 실행 2는 벽시계 33.93s 중 LLM 지연이
  5.76s뿐이다. 차이의 대부분은 임베딩 모델 첫 로딩(CPU, 수십 초)이다.
- **코퍼스를 8건 → 16건으로 늘렸을 때 항목 커버리지는 그대로였고(2/4), 인용 문서 수와
  초안 분량만 늘었다.** 커버리지를 올리려면 코퍼스 양보다 검색 방식(질의 재작성, top-k,
  청크 전략)이 더 중요할 수 있다는 신호다. 표본 1쌍이라 결론은 아니다.
- **`min_citations=1` / `max_revisions=2`는 근거 없이 정한 출발점이다.** 골든셋으로
  측정하기 전까지 적절한지 알 수 없다.

### 계속 열려 있는 것

- **사내 보안 정책상 무인증 엔드포인트 사용이 허용되는지 여전히 미확인.** ADR-004로
  사내 문서 투입을 범위 밖으로 두면서 **당장의 위험은 피했지만, 질문 자체는 남아 있다.**
  허용되지 않으면 서빙 경로를 다시 봐야 한다.
- **2026년 말 대체 서빙 경로.** 전환 *비용*은 낮춰뒀지만 **대체 경로 확보 자체는
  해결되지 않았다.** 만료가 다가올수록 선택지가 줄어든다.
- 감사 로그 보존 기간·접근 권한 요구사항 — 로컬 JSONL에는 이 개념이 없다.
- 골든셋 자동 채점 방식. `must_mention`이 의미 판정이라 현재 형태로는 자동화되지 않는다.
  LLM 심판을 쓰면 판정 모델이 또 하나의 변수가 되어 모델 고정 원칙(ADR-002)과 충돌한다.

## 주의

### Python 3.14 + Pydantic V1 경고 — 확인 결과 (session-03 숙제)

이번 세션에 **pydantic을 새로 도입하지 않았다.** State는 TypedDict, 나머지는 dataclass다
(`grep -rn "pydantic\|BaseModel" src/ scripts/ tests/` 결과 없음).

경고를 내는 패키지를 하나씩 확인했다:

| 패키지 | 경고 |
| --- | --- |
| langchain-core | 발생 (`_api/deprecation.py`) |
| **langfuse** (이번 세션 신규) | **발생** (`api/core/pydantic_utilities.py`) |
| langgraph / litellm / chromadb / sentence-transformers | 깨끗함 |

**결론: 지금 막을 필요 없다.** 평소 실행에서 67개 테스트 전부 통과하며, 경고를 에러로
승격(`-W error::UserWarning`)했을 때만 수집 단계에서 실패한다. 즉 **경고일 뿐 동작에
문제를 일으키지 않는다.**

다만 **위험 표면이 넓어졌다.** langfuse가 `pydantic.v1.datetime_parse`를 **임포트 시점에
실제로 사용**하는 반면 langchain-core는 deprecation 모듈에서만 건드린다. 3.14 + Pydantic V1
비호환이 실제 오류가 되는 시점에는 **langfuse가 먼저 깨질 가능성이 높다.**
Python 3.12/3.13으로 내릴지는 그때 판단해도 되지만, 판단 근거가 이제 langchain-core가
아니라 langfuse라는 점을 기억할 것.

### 실행 관련

- **지연을 잴 때 임베딩 모델 로딩을 분리할 것.** 프로세스가 질의 1건마다 새로 뜨는 현재
  방식에서는 매번 수십 초의 로딩 비용을 낸다. 상주 프로세스로 바꾸면 사라지는 비용이므로,
  섞어 재면 모델이 느린 것처럼 보인다. 이번 세션 수치도 벽시계와 LLM 지연을 나눠 적었다.
- 코드 실행은 레포 루트를 cwd로 한다 (session-02와 동일).
- 인덱스(`var/chroma/`)와 계측 로그(`var/traces/`)는 커밋하지 않는다. 재현의 기준은
  인덱스가 아니라 **`data/corpus/` 스냅샷 + 임베딩 모델 이름**이다.
- 임베딩 모델을 바꾸면 `python scripts/build_index.py --reset`이 필요하다. 안 하면
  검색 시 불일치 예외가 난다 (조용히 틀린 결과를 내지 않도록 일부러 그렇게 했다).

### 승인 게이트

`docs/governance.md`의 규칙은 그대로다. 이번 세션에서 한 일 중 승인이 필요한 것은 없었다 —
엔드포인트 호출은 기존 할당 자원이고, 코퍼스 수집은 공개 API 읽기이며, PyPI 설치와
Chroma 인덱스 생성은 로컬 파일 작업이다. 새 유료 리소스나 되돌리기 어려운 외부 상태를
만들지 않았다.
