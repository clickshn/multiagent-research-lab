# ADR-022: 골든셋 v2.0은 앵커의 온톨로지 메타 유무로 층화하고, 필터 측정에서 결측층을 분리 집계한다

- **Status:** Accepted
- **Date:** 2026-09-18
- **Decision:** 필터 규칙은 **strict**(온톨로지 메타가 없는 문서는 필터를 통과하지 못한다)로 두고,
  골든셋 각 케이스에 **앵커 문서의 메타 보유 여부를 사전 선언**해 층 A(필터 적격) /
  층 B(메타 결측) / 층 C(negative)로 나눈다. 재현율·점수 간격은 **층별로 따로 집계하며,
  층 A와 층 B를 합친 단일 평균을 Session 3의 판정 지표로 쓰지 않는다.**
  스냅샷 14건의 메타 backfill은 **하지 않는다**(기각 사유는 Alternatives (가)).
- **Scope:** multiagent-research-lab (`docs/eval/golden-set.json` v2.0 / `scripts/probe_retrieval.py` / Session 3 필터 판정 설계)
- **Decision Source:** Human

---

## Context

골든셋을 9건에서 30건으로 확대하면서 기존 9건의 앵커 문서를 전수 확인한 결과,
**positive 7건 중 6건의 기대 문서에 온톨로지 메타데이터가 아예 없다.**

```
GS-001  arXiv:2412.05449v1   meta=O  release_type=Paper  tech_domains=Agent|Eval/Governance|LLM
GS-002  arXiv:2602.03128v1   meta=X  (공백)
GS-003  arXiv:2405.16887v2   meta=X  (공백)     ← 기대 문서 2건 모두
        arXiv:2406.01893v2   meta=X  (공백)
GS-004  arXiv:2512.06196v1   meta=X  (공백)
GS-005  arXiv:2412.20138v7   meta=X  (공백)
GS-006  arXiv:2404.01023v1   meta=X  (공백)
GS-007  arXiv:2512.13930v1   meta=X  (공백)
```

ADR-020 Consequences가 경고한 "스냅샷 arXiv 14건에 `release_type`이 없다"가
**골든셋 쪽에서 최악의 형태로 실현된 상태다.** 14/37 = 37.8%라는 코퍼스 비율보다
골든셋 쪽 비율이 훨씬 나쁘다 — **필터 적격 positive가 현재 1건(GS-001)뿐이다.**

필터를 strict로 걸면 이 6건은 필터 품질과 무관하게 재현율이 0이 된다. 그 0이
전체 평균에 섞이면 Session 3은 **"필터가 나쁘다"를 읽게 되는데, 실제로 일어난 일은
"필터가 기대 문서를 볼 수조차 없었다"**이다. 두 문장은 다음 세션의 결론을 반대 방향으로
가른다.

동시에 이 결측을 없애는 방향(메타 backfill)은 **session-11 §5(생산자 레포 게이트 이식) →
§6(vLLM 이전)이 아직 실행되지 않아 이번 세션에서 실행 자체가 불가능하다**(session-12 §8 "주의").

## Decision

1. **필터 규칙은 strict다.** 온톨로지 메타가 없는 문서는 `release_type` 필터도
   `tech_domain` 필터도 통과하지 못한다. 운영 필터의 실제 동작이 그렇고,
   무엇보다 **null을 통과시키면 `tech_domain` 필터의 선택도가 파괴된다**(Rationale).

2. **골든셋 v2.0의 각 케이스에 `anchor_meta` 필드를 둔다.** 값은
   `"present"`(앵커 전건이 온톨로지 메타 보유) / `"missing"`(1건이라도 결측) /
   `"n/a"`(negative — 앵커 없음). **측정 전에 파일에 박아 넣는다.**

3. **층화 집계.** 재현율·평균 순위·점수 간격을 아래 3층으로 **각각** 낸다.

   | 층 | 정의 | 역할 |
   |---|---|---|
   | **A** | positive, `anchor_meta=present` | **Session 3 필터 판정의 주 지표** |
   | **B** | positive, `anchor_meta=missing` | **필터가 무엇을 잃는지의 측정값.** 버리지 않는다 |
   | **C** | negative (`expect_uncovered=true`) | 점수 간격·오탐 |

4. **층 A와 층 B를 합친 단일 재현율을 필터 판정에 쓰지 않는다.** 필터 없음(baseline)
   측정에서는 합산 수치도 함께 적는다 — Session 1 대비 연속성을 위해서다. 그러나
   **필터를 건 측정에서 합산값은 해석 불가 수치이므로 보고하지 않는다.**

5. **층 B는 "제외"가 아니라 "분리 보고"다.** 층 B의 필터 적용 후 재현율은
   **설계상 0이 나오는 것이 정상이며, 그 0이 곧 ADR-020이 경고한 37.8% 결측의 비용이다.**
   Session 3은 이 값을 반드시 함께 낸다.

6. **`tech_domain` 필터는 프로브 단계의 후처리로 적용한다.** `tech_domains`는 `|` 연결
   문자열이고 Chroma 1.5.5의 메타데이터 연산자에는 부분 일치가 없다(ADR-020 Rationale).
   k=37 전수를 받아 **프로브 스크립트 안에서** 거른다 — 재인덱싱도, `src/tools/retrieval.py`
   변경도 필요 없다.

## Rationale

**핵심은 "결측이 재현율을 깎느냐"가 아니라 "두 필터를 서로 비교할 수 있느냐"다.**

이번 골든셋 설계의 목적은 `release_type` 필터와 `tech_domain` 필터의 **차이**로
"필터 효과"와 "오염 제거분"을 가르는 것이다. 그러려면 **두 필터가 같은 모집단 위에서
작동해야 한다.** 결측 14건을 통과시키면(대안 (나)) 이 조건이 비대칭으로 깨진다:

| 필터 | strict 생존 문서 | null 통과 시 생존 | 생존자 중 **걸러지지 않은 null**의 비율 |
|---|---:|---:|---:|
| `release_type = Paper` | 11 | 25 | 14/25 = **56.0%** |
| `tech_domain = Reasoning` | 2 | 16 | 14/16 = **87.5%** |

`tech_domain` 쪽이 훨씬 심하게 희석된다. 선택도가 높은 도메인일수록 더 나빠지는데,
**(a) 유형 케이스는 정확히 그 선택도 높은 도메인을 쓰려고 만드는 것이다.**
즉 null 통과는 이번 세션이 만들려는 대조군을 **가장 필요한 지점에서 무력화한다.**

층화(대안 (다))는 **표본을 줄이는 대신 비교 가능성을 산다.** 현재 필터 적격 positive는
1건(GS-001)뿐이고, 확대 후 층 A는 13~15건이 된다 — **오늘보다 13배 이상 나은 표본이며,
층 B를 섞어 얻는 23건보다 해석 가능한 23건이 아니라 해석 가능한 13~15건이 낫다.**

**사전 선언이 이 결정의 방어선이다.** 측정 후에 "이 6건은 빼자"고 하면 체리피킹이다.
`anchor_meta`를 **골든셋 파일에 측정 전에 박아 넣고** 커밋하는 것이 그것과 다른 점이다.
층 B의 케이스 목록은 필터를 걸기 전에 이미 고정돼 있고, 그 목록은
**필터 설계가 아니라 코퍼스 적재 이력이 결정한 것**이라 필터에 유리하게 고를 여지가 없다.

## Evidence

- 골든셋 기존 9건 앵커 전수 확인: positive 7건 중 **6건이 `anchor_meta=missing`**,
  기대 문서 기준 8건 중 **7건 결측**. 필터 적격 positive는 **GS-001 1건뿐**.
- 코퍼스 37건 중 온톨로지 메타 보유 **23건 / 결측 14건**(37.8%) — session-12 §1과 일치.
- 결측 14건은 **전원 스냅샷 arXiv**다. `source=news` 13건과 계약 경로 arXiv 10건에는
  결측이 없다. **결측 여부가 문서군과 완전히 겹친다**(Alternatives (가)의 기각 근거).
- `tech_domains` 라벨 분포(23건 기준): Eval/Governance 13 · LLM 10 · Agent 7 ·
  Application/Product 7 · Safety/Alignment 5 · Training/Finetuning 5 · Multimodal 3 ·
  Reasoning 2 · Data/Synthetic·Infra/MLOps·Hardware/Chip·Inference/Serving 각 1.
- Chroma 1.5.5 메타데이터 연산자에 부분 일치 없음 → `|` 연결 문자열 필터는 후처리로만 가능.

## Alternatives

**(가) 스냅샷 14건에 vLLM으로 온톨로지 메타를 채운다. — 기각 (2개 사유, 각각 단독으로 충분)**

1. **실행 불가.** vLLM 추출 경로는 session-11 §5(생산자 레포 게이트 이식) → §6(vLLM 이전)
   순으로 막혀 있고 **둘 다 아직 안 됐다**(session-12 §8). 비용이 0인 것과 경로가 열려 있는
   것은 다르다.
2. **추출 모델과 문서군이 완전 공선(collinear)이 된다.** backfill하면
   `extraction_model`이 `claude-opus-5` 23건 / `gemma-4-31B-it` 14건으로 갈리는데,
   **gemma 라벨이 붙는 14건은 전부 스냅샷 arXiv이고 Opus 라벨 23건에는 스냅샷이 하나도 없다.**
   → provenance로 **구분은 된다**(`extraction_model`·`export_id`·`prompt_sha256`가 문서별로
   남는다). 그러나 **구분되는 것과 분리되는 것은 다르다.** 두 집단이 문서 출신과 1:1로
   겹치므로, 층별 차이가 나와도 "모델 때문인가 문서군 때문인가"를 **어떤 통계로도 가를 수 없다.**
   session-12 §0이 경고한 "필터 효과에 추출 모델 교체가 섞인다"를 **코퍼스에 영구적으로
   구워 넣는 선택**이다.
3. 부가로, 코퍼스를 바꾸면 Session 3이 "필터 하나만 바꾼다"는 조건을 잃는다(ADR-002).

  → **재검토 조건:** vLLM 이전이 끝나고 **전체 37건을 같은 모델로 재추출**할 수 있게 되면
    공선성이 사라진다. 그때는 **필터 배선과 다른 세션에서, 코퍼스 단독 변경으로** 한다.

**(나) 필터에서 null을 통과시킨다. — 주 규칙으로는 기각, 2차 arm으로 채택**

결측이 재현율을 깎지 않는다는 장점은 실재한다. 그러나 위 표대로 **`tech_domain` 필터를
`release_type` 필터보다 훨씬 심하게 희석시켜(87.5% vs 56.0%) 두 필터의 차이를
"오염 제거분"으로 읽는 이번 설계의 산술을 깨뜨린다.** 희석량이 필터마다 다르므로
두 필터의 델타에서 상쇄되지도 않는다.

  → **다만 버리지 않는다.** Session 3은 strict를 주 arm으로 하되 **null-통과 arm을 함께
    측정한다.** 두 arm의 차이가 곧 "결측 14건이 필터 결과에 미치는 영향"의 직접 측정값이고,
    그 값은 (가)를 언제 해야 하는지 판단할 근거가 된다.

**(다) 층화 + 분리 집계. — 채택** (본문 Decision)

**(라) 결측 앵커 케이스를 골든셋에서 아예 뺀다. — 기각.** 가장 단순하지만
GS-002~007은 v1.0부터 이어져 온 **Session 1·5·12와의 유일한 연속 비교 지점**이다.
빼면 "코퍼스 16 → 37에서 순위가 전부 떨어졌다"는 추세를 이어서 볼 수 없다.
분리 집계는 이 연속성을 지키면서 오염만 막는다.

## Consequences

- ⚠️ **필터 적용 측정에서 층 A의 n이 13~15로 작다.** n=14에서 1건은 약 7%p다.
  **방향은 읽되 크기는 신뢰하지 않는다** — ADR-005 Amendment §5의 경고가 그대로 유효하다.
  층 A를 더 키우려면 코퍼스를 늘려야 한다(2단계 220건).
- ⚠️ **층 B의 필터 후 재현율은 0이 정상이다.** 이 값을 보고 "필터가 망가졌다"고 읽으면
  안 된다. 판정문에 그렇게 적는다.
- Session 3의 보고 형식이 고정된다: **층 A / 층 B / 층 C 3표 + null-통과 2차 arm.**
  평균 1개짜리 보고는 이 ADR 위반이다.
- `scripts/probe_retrieval.py`가 `anchor_meta`를 읽어 층별 집계를 내도록 확장된다.
  **`src/tools/retrieval.py`는 계속 변경 0줄이다** — `tech_domain` 후처리도 프로브 안에서 한다.
- 골든셋 v1.0(9건)으로 잰 과거 수치와 v2.0 합산 수치는 **케이스 구성이 달라 직접 비교
  불가**다. 연속 비교는 **GS-001~009 부분집합으로만** 한다. 이것도 프로브가 따로 낸다.

## Reversibility

- **Reversible:** Yes
- **Rollback:** `anchor_meta` 필드를 무시하고 합산 집계로 돌아가면 된다. 데이터 손실 없음.
- **Migration Cost:** Low — 골든셋 JSON 필드 1개와 프로브 집계 로직뿐이다.

## Review Trigger

- **vLLM 이전(session-11 §6) 완료 시** — 37건 전수 재추출이 가능해지면 (가)의 공선성이
  사라진다. 그 시점에 층 B를 없앨지 재검토한다. **단, 필터 배선과 같은 세션에서 하지 않는다.**
- **2단계 220건 반입 시** — 신규 문서는 전부 메타를 갖고 들어오므로 층 A가 급격히 커진다.
  층 B의 상대 비중이 작아지면 분리 집계의 필요성 자체를 다시 본다.
- **Session 3에서 strict arm과 null-통과 arm의 차이가 작게 나오는 경우** — 결측 14건이
  실제로는 결과를 거의 바꾸지 않는다는 뜻이므로, 규칙을 (나)로 단순화할 수 있다.
