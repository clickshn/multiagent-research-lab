# ADR-021: 외부 LLM 벤더 비의존 전제 위반 기록 — 승인 게이트에 "대상 엔드포인트" 항목을 넣고 도구·코드 계층에서 집행한다

- **Status:** Accepted
- **Date:** 2026-09-17
- **Decision:** Session 0.5a에서 계약 검증용 추출을 외부 Anthropic API로 실행해 전제를 위반한 사실을 기록한다. 승인 게이트 양식에 **"대상 엔드포인트가 `VLLM_BASE`인가"를 1번 필수 항목**으로 넣고, `.claude/hooks/check-external-llm.sh`(도구 계층)와 `src/providers/egress.py`(코드 계층)로 집행한다. **2단계 220건은 이 전제가 정리되기 전에는 외부 API로 실행하지 않는다.**
- **Scope:** multiagent-research-lab (승인 게이트 / 훅 / 프로바이더 계층) — 위반이 일어난 실행 코드는 생산자 레포 `ai-news-ontology`에 있다
- **Decision Source:** Human

---

## Context

### Problem

**Session 0.5a에서 계약 검증용 1단계 추출을 외부 Anthropic API(`claude-opus-5`)로
실행했다.** 이 프로젝트의 세션 공통 규칙은 "KT Cloud AI Nexus 엔드포인트 외 신규 외부
API 호출 금지"다. 승인 게이트가 있었고, 통과했다.

게이트는 **목적·모델명·건수·예상 비용**을 물었고 **전부 정확히 답변됐다.** 승인도
받았다. 그런데 **"이 호출이 전제를 위반하는가"는 아무도 묻지 않았다.**

> **게이트가 있었고 통과했는데, 게이트가 확인해야 할 것을 확인하지 않았다.**
> 양식이 묻는 것은 전부 **비용의 크기**였다. 규칙 적합성을 묻는 항목이 없었으므로,
> 답이 전부 맞아도 위반은 걸러지지 않는다. 이 게이트는 **비용 게이트**였지
> 규칙 게이트가 아니었다.

**숨기거나 사후 정당화하지 않는다.** 아래는 실제로 나간 것이다.

#### 나간 데이터 — 30건이 아니라 49건이다

| 단계 | 모델 | 건수 | 내용 |
|---|---|---:|---|
| 관련성 게이트 | `claude-haiku-4-5` | **49건** | 보존 30 + 스킵 19(전부 GeekNews). **판정된 기사 전부의 본문이 나갔다** |
| 구조화 추출 | `claude-opus-5` | **30건** | 본문 + 시스템 프롬프트 v4 + structured output 스키마 |

- 요약·리포트에서 이 사건을 "30건"으로 부르는 것은 **추출 건수**이고, **본문이 벤더로
  나간 기사 수는 49건**이다. 스킵된 19건도 "판정하기 위해" 나갔다.
- 프롬프트도 함께 나갔다. 추출 입력은 본문 길이와 무관하게 건당 약 9,200토큰으로
  거의 고정인데, **입력의 대부분이 우리 시스템 프롬프트와 스키마**라는 뜻이다.
- 출처 구성: Hugging Face Blog 5 · GeekNews 10(+스킵 19) · arXiv cs.CL 8 ·
  MARA 스냅샷 시드 2 · Google DeepMind Blog 2 · OpenAI News 3.
- **사내 데이터·고객 데이터는 0건이다.** 코퍼스가 공개/합성 자료로 한정돼 있기
  때문이다(ADR-004).

  ⚠️ **이것은 우연이 아니라 다른 규칙이 막아 준 것이다.** ADR-004는 "인용 정확도를
  재려면 원문이 공개돼 검증 가능해야 한다"는 측정 설계 때문에 있는 규칙이지, 데이터
  유출을 막으려고 만든 규칙이 아니다. 목적이 다른 규칙이 우연히 겹쳐서 피해가 작았다.
  **전제를 지키는 규칙 자체는 작동하지 않았다.** 다음에 ADR-004가 완화되면
  (실데이터 투입 결정) 이번과 같은 일이 나도 막아 주는 것이 없다.

#### 비용

| 항목 | 금액 |
|---|---:|
| 보존 30건 실측 | $2.058 |
| 게이트 스킵 19건 추정 | 약 $0.067 |
| **이번 실행 총액** | **약 $2.13** |
| 2단계 220건 (**미실행**) | 약 $16 |

**금액은 이 ADR의 논점이 아니다.** $2.13은 작다. 작아서 통과한 것이 이 사건의 성질을
말해 준다 — 게이트가 금액만 봤다면 $2.13은 언제나 통과한다.

### Constraints

- **이 프로젝트는 "폐쇄망"이 아니다.** 세션 2에서 용어를 정정했다
  (`docs/security/owasp-notes.md` §0). 실제 제약은 **외부 LLM 벤더 비의존**이고,
  기준은 네트워크 도달 가능성이 아니라 **데이터가 어느 벤더의 모델로 향하는가**다.
  위반 판정은 정정된 기준으로도 그대로 성립한다 — 오히려 정정된 기준에서 더 명확하다.
  ⚠️ 그런데 **이름이 흔들리는 규칙은 게이트 항목으로 번역되지 않았다.** "폐쇄망"이라고
  부르면 "인터넷이 되니까 괜찮다"로 읽히고, "외부 벤더 비의존"이라고 불러야
  "목적지가 어디인가"라는 질문이 나온다. 그 질문이 양식에 없었던 것과 무관하지 않다.
- **"외부 API 호출"의 정의가 어디에도 없었다.** 이 세션을 도는 에이전트 자신이
  `claude-opus-5`(Anthropic API) 위에서 돈다. 정의가 없으면 "외부 API 호출 0건"이라는
  보고조차 무엇을 세는지 모호하다. **이 규칙이 가리키는 것은 파이프라인·산출물이
  거치는 경로**이지 하네스 자체가 아니다 — 이제 그렇게 적는다.
- 실행 코드는 **생산자 레포(`C:\ai-news-ontology-1`)** 에 있다. `config.yaml`이
  `llm.provider: anthropic`으로 세 단계(관련성 게이트 / 추출 / eval judge)를 전부 벤더에
  묶어 두고 있다. **MARA에는 벤더 SDK 의존이 없다**(`requirements.txt`에 litellm뿐).
  즉 규칙은 여기 있고 위반은 저기서 났다.
- ADR-002가 서빙을 vLLM(`gemma-4-31B-it`)으로 고정해 두었는데, **코퍼스 생성 경로만
  외부 벤더를 쓰고 있다.** 같은 시스템의 입력을 만드는 단계가 다른 원칙 위에 있다.

### 플레이북 8장의 같은 패턴 — **다섯 번째 사례다**

> **규칙이 있어도, 그 규칙을 집행하는 장치가 규칙을 만족하는지는 따로 확인해야 한다.**

`docs/INTERVIEW_NOTES.md` §4에 앞의 네 건이 있다.

| # | 세션 | 무엇이 어긋났나 |
|---|---|---|
| 1 | 6 | 마스킹 규칙은 있는데 `redacted()`가 **아무것도 가리지 않았다** |
| 2 | 7 | 게이트를 세운 직후 **PowerShell 도구로 우회됐다** |
| 3 | 8 | 최소 권한을 **설계한 사람의 권한이 최소가 아니었다** |
| 4 | 8 | **검증 방법 자체가 틀렸다** (IAM 전파 지연 중의 통과를 검증으로 읽음) |
| **5** | **0.5a** | **게이트의 질문 목록에 규칙이 없었다** |

**앞 네 건과 종류가 하나 더 안쪽이다.** 1~3은 장치가 규칙을 만족하지 않은 것이고,
4는 장치를 검사하는 방법이 틀린 것이다. 이번 것은 **장치가 고장 난 것이 아니라
처음부터 다른 것을 재고 있었다** — 비용을 재는 장치가 규칙 자리에 놓여 있었고,
그것이 정상 작동했다. 그래서 실패 신호가 하나도 나지 않았다.

## Decision

### Selected

- **Technology:** PreToolUse 훅(Bash) + Python 데이터클래스 불변식. 새 의존성 없음.
- **Architecture:** 같은 규칙을 **두 계층에서 독립적으로** 집행한다.

  | 계층 | 파일 | 막는 것 |
  |---|---|---|
  | 도구 | `.claude/hooks/check-external-llm.sh` | Bash·PowerShell **명령 문자열**의 벤더 호스트 / SDK 임포트 / API 키 주입 / 외부 모델 CLI / 생산자 파이프라인 실행. 차단은 exit 2 |
  | 코드 | `src/providers/egress.py` + `ProviderSettings.__post_init__` | `VLLM_BASE`를 벤더로 바꿔 목적지를 돌리는 경로. **객체 생성 시점**에 `ExternalEndpointError` |

- **Implementation:**
  1. **승인 게이트 양식에 1번 항목을 넣는다** — "대상 엔드포인트가 `VLLM_BASE`인가".
     아니오는 **승인 대상이 아니라 규칙 위반**이다. `docs/governance.md`,
     `.claude/rules/external-llm.md`, `.claude/rules/security.md` 세 곳에 적는다 —
     ADR에만 있으면 다음 세션이 읽지 않는다.
  2. **모델명으로 1번을 대신하지 않는다.** 같은 모델 이름이 양쪽에 있을 수 있고,
     판정 기준은 이름이 아니라 목적지다.
  3. 예외는 `.claude/external-llm-approved` 파일로만 열린다(1회용, `.gitignore` 대상).
  4. **2단계 220건(약 $16)은 이 전제가 정리되기 전에는 외부 API로 실행하지 않는다.**
  5. 추출 단계를 KT Cloud vLLM으로 옮기는 것을 다음 세션 과제로 등록하고,
     **판정 기준을 데이터 보기 전에 사전 등록한다**
     (`docs/eval/preregistration-extraction-on-vllm.md`).
  6. **생산자 레포는 이번 세션에서 건드리지 않는다.** 그쪽 게이트는 **미구현으로 남는다**
     (Consequences 참조).

## Rationale

1. **문서에 적는 것으로는 안 지켜진다는 것이 이번 사건이다.** 규칙은 이미 있었다.
   없었던 것은 **그 규칙을 묻는 질문**이다. 그래서 질문을 양식에 고정하고, 양식을
   사람이 기억하는 것에 기대지 않도록 도구 계층에 같은 판정을 심었다.
2. **비용 항목과 규칙 항목은 다른 축이다.** 비용은 크기를 재고 규칙은 가부를 가른다.
   한 양식에 섞으면 규칙 위반이 "작은 비용"으로 환산돼 통과한다. 1번을 **맨 앞에**
   두고 "아니오면 여기서 멈춘다"고 적은 이유다.
3. **두 계층을 둔 이유는 서로의 사각을 메우기 때문이다.** 훅은 명령 문자열만 보므로
   스크립트 파일 안을 못 본다. 코드 가드는 우리 코드 안에서만 유효하다. 겹치는 부분이
   아니라 **안 겹치는 부분**을 보고 둘을 두었다.
4. **거부 목록이 불완전하다는 것을 전제로 설계했다.** 실제 허용 목록 역할을 하는 것은
   "프로바이더 계층이 `VLLM_BASE` 하나만 읽는다"는 설계(ADR-003)이고, 거부 목록은
   그 설계가 환경변수 한 줄로 무너지는 것을 막는 2차 방어선이다. 목록을 늘리는 것으로
   한계가 없어지지 않는다.
5. **막지 못하는 것을 산문이 아니라 테스트에 고정했다.** 알려진 우회 5건을 케이스 파일에
   **기대값 0(통과)** 으로 넣었다. 인젝션 테스트에서 탐지 우회 3종을 고의로 통과시켜
   한계를 고정한 것과 같은 방식이다. 언젠가 이 줄이 exit 2가 되면 그때 기대값을 바꾼다.

## Evidence

- **Experiment:** 게이트 검사 **41건 전부 통과** (`bash tests/gate/external_llm_cases.sh`).
  차단 19 / 오탐 대조 14 / 알려진 우회(고의 통과) 5 / 승인 파일 2 / fail-closed 1.
- **Experiment:** 실제 우회 시도 — **세션 안에서 직접 해 봤다.**

  | 시도 | 결과 |
  |---|---|
  | Bash 도구로 벤더 호스트가 든 명령 | **차단(exit 2)** |
  | PowerShell 도구로 같은 시도 (session-07의 우회 경로) | **차단(exit 2)** |
  | `VLLM_BASE`를 벤더로 교체 후 설정 로딩 | **차단** (`ExternalEndpointError`) |
  | 파서(jq·python)를 모두 감춘 환경 | **차단** (fail-closed) |
  | **스크립트 파일 안에 벤더 호출을 숨기고 `python <파일>` 실행** | ⚠️ **통과 — 막지 못한다** |

- **Experiment:** 훅이 **이번 세션에서 즉시 유효**했다. `settings.json` 변경 후 재시작
  없이 두 도구 모두 차단됐다.
- **Production Data:** `pytest tests/ -q` → **177 passed** (기준선 156 + 신규 21).
- **Cost:** 이번 세션 외부 API 호출 **0건**. 위반 실행분은 $2.13, 2단계 약 $16은 미실행.
- **Cost:** 훅은 모든 Bash·PowerShell 호출마다 돈다. 파서 탐색 순서를
  `python3 → python`에서 `python → python3`으로 바꿔 호출당 약 1.9s를 약 0.2s로 줄였다
  (이 머신의 `python3`은 pyenv-win shim이다).

## Alternatives

### (가) 문서에만 적고 사람이 지킨다

- **Pros:** 비용 0. 오탐도 0.
- **Cons:** 이번 위반이 정확히 그 상태에서 났다.
- **Rejected because:** 규칙은 이미 문서에 있었고, 그래서 이 사건이 났다.

### (나) `permissions.deny`로 하드 차단

- **Pros:** 가장 강하다. 훅보다 앞단이라 우회 여지가 적다.
- **Cons:** `deny`는 **승인 파일로도 대화형 승인으로도 풀리지 않는다**(session-07 실증).
- **Rejected because:** 이 규칙의 상태는 "영구 금지"가 아니라 **"승인 없이는 금지"**다.
  하드 차단은 규칙을 잘못 표현하고, 정당한 승인 경로까지 막아 결국 사람이 게이트를
  통째로 끄게 만든다.
- **Recheck if:** 전제가 "영구 금지"로 확정되는 경우 — 조직이 외부 벤더 사용 불가를
  확정하면 `deny`가 맞는 표현이 된다.

### (다) 네트워크 계층에서 차단한다 (프록시 / 방화벽 / egress 정책)

- **Pros:** 스크립트 파일 경유·난독화까지 전부 막는다. 유일하게 완전한 해법이다.
- **Cons:** 우리가 그 계층의 소유자가 아니다. 개발 환경은 인터넷 경유이고
  (ADR-002 Amendment), 엔드포인트도 우리 소유가 아니다.
- **Rejected because:** 실행 권한이 없다. 할 수 있는 것은 도구·코드 계층뿐이다.
- **Recheck if:** 사내 보안 정책 결정으로 egress 통제가 가능해지는 경우 — 무인증
  엔드포인트 허용 여부와 **같은 게이트에 묶인다**(README §5.7).

### (라) 거부 목록 대신 허용 목록을 코드에 고정한다

- **Pros:** 새 벤더가 생겨도 자동으로 막힌다. 목록 유지보수가 없다.
- **Cons:** 허용할 호스트를 코드에 적어야 한다.
- **Rejected because:** **엔드포인트를 코드에 고정하지 않는다**(ADR-003, governance
  "코드 규칙")와 정면으로 충돌한다. 엔드포인트 교체가 코드 변경이 되는 순간
  2026년 말 서빙 전환의 비용이 올라간다.

## Consequences

### Positive

- 규칙이 **양식·훅·코드 세 곳**에 있다. 한 곳을 안 읽어도 나머지가 걸린다.
- 승인 게이트가 **가부를 가르는 항목**을 갖게 됐다. 이전 양식은 크기만 쟀다.
- 막지 못하는 범위가 **테스트에 적혀 있다.** 다음 사람이 "이건 막히겠지"로 넘어가지 않는다.

### Negative

- **훅이 모든 Bash·PowerShell 호출마다 돈다.** `check-deploy-approval.sh`에 이어 두 번째다.
  파서 순서를 고쳐 비용을 줄였지만 0은 아니다.
- **자기참조 오탐.** 벤더 호스트를 예시로 적는 명령은 그 자체가 차단된다. 이 ADR도
  Write 도구로 작성했다 — 회피가 아니라 정상 경로다(`.claude/rules/external-llm.md`).
- **테스트가 약 60초 늘어난다.** 케이스마다 훅 프로세스를 실제로 띄우기 때문이고,
  모킹하면 "읽는 것과 돌려 보는 것은 다르다"는 이 게이트의 존재 이유를 스스로 어긴다.

### Risks

- ⚠️ **스크립트 파일 경유는 막지 못한다.** `python <파일>`의 명령줄에는 벤더 흔적이
  없다. 세션 안에서 **실제로 뚫어서 확인했다.** 셸 스크립트·Makefile·난독화도 같다.
- ⚠️ **거부 목록은 구조상 불완전하다.** 새 벤더·사설 프록시는 통과한다.
- ⚠️ **에이전트 자신의 모델 호출과 서브에이전트, MCP 경유 호출은 범위 밖이다.**
- 🔴 **생산자 레포에는 이 게이트가 없다.** 실제 위반이 난 코드가 거기 있는데
  이번 세션에서 건드리지 않기로 했으므로, **지금 이 순간 같은 위반이 다시 가능한
  상태다.** MARA의 훅은 MARA 세션에서만 돈다. 생산자 레포 반영은 미완이며
  handoff의 차단 항목으로 넘긴다.
- **이미 나간 데이터는 회수할 수 없다.** 이 ADR은 재발을 막을 뿐이다.

## Reversibility

- **Reversible:** Partial
- **Rollback:** 게이트는 훅 등록 한 줄과 `__post_init__` 한 줄을 지우면 없어진다.
  **그러나 이미 나간 49건과 프롬프트는 되돌릴 수 없다** — 이 ADR에서 되돌릴 수 있는
  것은 장치뿐이고, 위반의 결과는 롤백 대상이 아니다.
- **Migration Cost:** Low

## Review Trigger

- **2단계 220건 실행을 다시 논의할 때** — 전제(외부 벤더 비의존)가 정리되지 않았으면
  금액과 무관하게 실행하지 않는다.
- **추출 단계의 vLLM 이전이 끝났을 때** — 위반 경로 자체가 사라지므로 게이트의
  적용 범위를 다시 본다.
- **ADR-004가 완화될 때(실데이터 투입)** — 피해를 줄여 준 것이 ADR-004였으므로,
  그것이 풀리면 이 게이트만 남는다. 그 전에 생산자 레포 반영이 끝나 있어야 한다.
- **조직이 외부 벤더 사용 불가를 확정할 때** — (나)의 `permissions.deny`가 맞는
  표현이 된다.
- **egress 통제가 가능해질 때** — (다)가 유일하게 완전한 해법이므로 다시 본다.
