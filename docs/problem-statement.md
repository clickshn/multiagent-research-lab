# Problem Statement — multiagent-research-lab

> 상태: 초안 (v0.2, 2026-09-15). TBD 항목은 이후 세션에서 확정한다.
> v0.2에서 제약 섹션을 서빙 실태에 맞게 재작성했다 (ADR-003).

## 1. 문제

**누구의 문제인가.** 사내 규정·기술 문서·과거 프로젝트 산출물을 근거로 조사 보고서를
써야 하는 실무자(기획·법무·엔지니어링 검토 담당). 이들은 질문 하나에 답하기 위해
사내 문서 저장소를 반복 검색하고, 흩어진 근거를 직접 모아 요약한다.

**어떤 문제인가.** 조사 1건에 수 시간이 들고, 결과물의 근거가 어디서 왔는지
사후에 재현하기 어렵다. 일반 챗봇을 쓰면 요약은 빨라지지만 출처가 불분명해
그대로 업무에 쓸 수 없고, 검토·재확인 비용이 오히려 늘어난다.

**어떤 제약 아래서인가.** 대상 문서가 사외 반출 불가 등급이라 외부 SaaS LLM에
올릴 수 없다. 추론은 자체 호스팅한 오픈소스 모델로만 수행하며, 문서 내용이 타사
LLM 벤더로 나가지 않아야 한다.

> **범위 주의.** 위 서술은 이 시스템이 **가정하는 사용 맥락**이며, 이 레포는 그
> 맥락을 상정한 **아키텍처 실습**이다. 실제로 투입하는 데이터는 공개 자료
> (arXiv 논문 초록, 공개 AI/기술 뉴스)로 한정하며 **실제 사내 기밀 문서는 넣지
> 않는다.** 현 서빙 엔드포인트가 무인증 공개 접근이라 사내 문서 투입은 회사 보안
> 정책 검토가 별도로 필요한 문제이고, 이 포트폴리오 프로젝트의 범위를 벗어난다
> (ADR-004).

## 2. 제약

- **외부 SaaS LLM API 미사용 — 외부 LLM 벤더 비의존.** OpenAI·Anthropic 등 타사
  관리형 LLM API를 쓰지 않는다. 추론은 자체 호스팅한 오픈소스 모델로만 수행하며,
  사내 문서 내용과 질의가 타사 LLM 벤더로 전송되지 않는다.

  이것은 **완전한 물리적 망분리(air-gap)가 아니다.** 현재 추론 경로인 KT Cloud
  AI Nexus의 vLLM 엔드포인트는 외부 인터넷에서 도달 가능한 HTTPS 프록시다. 따라서
  "인터넷 연결 없음"은 이 시스템의 제약이 아니며, 실제 핵심 제약은 **데이터가
  어느 벤더의 모델로도 나가지 않는다**는 것이다. 모델 가중치와 추론 과정은 우리가
  통제하는 서빙 경로 안에 머문다.

  이 구분이 중요한 이유: 망분리를 전제하면 패키지 레지스트리·임베딩 서비스까지
  전부 차단된 것으로 설계하게 되는데, 실제로는 그렇지 않아 불필요한 제약을
  스스로 지게 된다. 반대로 벤더 비의존을 놓치면 "편의상 외부 API 하나만" 같은
  결정이 데이터 반출로 이어진다. 판단 기준은 **네트워크 도달 가능성이 아니라
  데이터가 향하는 곳**이다.

- **현 서빙 자원은 2026년 말까지만 유효.** 이 엔드포인트는 정부지원 GPU 자원
  할당으로 무료 사용 중이며 2026년 말 만료된다. 이후 대체 서빙 경로(자체 GPU 기동,
  다른 할당 자원, 유료 전환 등)로 전환해야 한다. 따라서 엔드포인트 교체 비용이
  낮게 유지되도록 설계해야 한다 — 모델 호출은 프로바이더 추상화 계층 뒤에 두고,
  엔드포인트·모델 이름은 설정으로 주입한다 (ADR-003).

- **GPU 자원 제한.** 가용 GPU는 소수이며 다른 워크로드와 공유될 수 있다. 모델 크기,
  동시 요청 수, KV 캐시 예산이 설계 변수다. 에이전트 수를 늘리는 설계는
  곧 GPU 예산 증가를 뜻하므로 항상 자원 예산과 함께 판단한다.
- **엔드포인트 URL이 곧 접근 권한.** 현 엔드포인트는 인증을 요구하지 않고 어떤
  네트워크에서든 접근 가능하다. 별도 접근 통제를 추가하는 것은 우리 범위 밖이므로
  (엔드포인트 소유자가 아니다), URL을 시크릿으로 취급하는 것이 유일한 통제 수단이다.
  취급 원칙은 `README.md` "보안 / 운영"과 `docs/governance.md` 참조.
- **감사 로그 필요.** 어떤 질의에 대해 어떤 문서를 검색했고, 어떤 프롬프트로
  어떤 모델이 무엇을 답했는지 사후 재현 가능한 형태로 남아야 한다.
  로그 자체도 우리가 통제하는 인프라(self-host)에 저장하며, 외부 SaaS 관측 도구로
  내보내지 않는다.
- **재현성.** 동일 질의에 대해 파이프라인 구성(모델 버전, 인덱스 스냅샷, 프롬프트 버전)이
  같으면 결과를 재현할 수 있어야 한다.

## 3. 목표

1. **리서치 시간 단축** — 실무자가 질의를 입력하면 개요·근거·초안까지 자동 생성해,
   사람은 검증과 편집에만 집중한다.
2. **근거(출처) 항상 제시** — 생성된 모든 주장 문장에 출처 문서와 위치를 붙인다.
   근거를 찾지 못하면 문장을 만들지 않고 "근거 없음"으로 표시한다. 이것이
   요약 품질보다 우선하는 제약이다.
3. **운영 가시성** — 각 에이전트 단계의 입력·출력·지연·토큰 사용량을 계측해,
   품질 저하가 발생했을 때 어느 단계에서 생긴 문제인지 특정할 수 있게 한다.

### 비목표 (현 단계)

- 문서 원본의 편집·관리 기능 (기존 문서 저장소가 담당)
- 다국어 지원 (1차는 한국어 + 영어 문서 혼재 환경만)
- 실시간 스트리밍 대화형 UX (배치성 리서치 요청부터 시작)
