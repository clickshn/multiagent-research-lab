# Problem Statement — multiagent-research-lab

> 상태: 초안 (v0.1, 2026-09-15). TBD 항목은 이후 세션에서 확정한다.

## 1. 문제

**누구의 문제인가.** 사내 규정·기술 문서·과거 프로젝트 산출물을 근거로 조사 보고서를
써야 하는 실무자(기획·법무·엔지니어링 검토 담당). 이들은 질문 하나에 답하기 위해
사내 문서 저장소를 반복 검색하고, 흩어진 근거를 직접 모아 요약한다.

**어떤 문제인가.** 조사 1건에 수 시간이 들고, 결과물의 근거가 어디서 왔는지
사후에 재현하기 어렵다. 일반 챗봇을 쓰면 요약은 빨라지지만 출처가 불분명해
그대로 업무에 쓸 수 없고, 검토·재확인 비용이 오히려 늘어난다.

**어떤 제약 아래서인가.** 대상 문서가 사외 반출 불가 등급이라 외부 SaaS LLM에
올릴 수 없다. 시스템 전체가 폐쇄망 안에서 동작해야 한다.

## 2. 제약

- **인터넷 연결 없음.** 외부 LLM API·임베딩 API·패키지 레지스트리를 런타임 경로에
  둘 수 없다. 추론 모델은 사내 GPU에서 직접 서빙해야 하고, 모델 가중치·의존성은
  사전 반입 절차를 거쳐야 한다.
- **GPU 자원 제한.** 전용 GPU는 소수이며 다른 워크로드와 공유한다. 모델 크기,
  동시 요청 수, KV 캐시 예산이 설계 변수다. 에이전트 수를 늘리는 설계는
  곧 GPU 예산 증가를 뜻하므로 항상 자원 예산과 함께 판단한다.
- **감사 로그 필요.** 어떤 질의에 대해 어떤 문서를 검색했고, 어떤 프롬프트로
  어떤 모델이 무엇을 답했는지 사후 재현 가능한 형태로 남아야 한다.
  로그 자체도 폐쇄망 안에 저장한다.
- **재현성.** 동일 질의에 대해 파이프라인 구성(모델 버전, 인덱스 스냅샷, 프롬프트 버전)이
  같으면 결과를 재현할 수 있어야 한다.

## 3. 목표

1. **리서치 시간 단축** — 실무자가 질의를 입력하면 개요·근거·초안까지 자동 생성해,
   사람은 검증과 편집에만 집중한다.
2. **근거(출처) 항상 제시** — 생성된 모든 주장 문장에 출처 문서와 위치를 붙인다.
   근거를 찾지 못하면 문장을 만들지 않고 "근거 없음"으로 표시한다. 이것이
   요약 품질보다 우선하는 제약이다.
3. **운영 가시성** — 각 에이전트 단계의 입력·출력·지연·토큰 사용량을 계측해,
   품질 저하가 발생했을 때 어느 단계에서 생긴 문제인지 특정할 수 있게 한다.

### 비목표 (현 단계)

- 문서 원본의 편집·관리 기능 (기존 문서 저장소가 담당)
- 다국어 지원 (1차는 한국어 + 영어 문서 혼재 환경만)
- 실시간 스트리밍 대화형 UX (배치성 리서치 요청부터 시작)
