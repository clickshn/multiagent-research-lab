### 초안에서 확인된 것

근거가 붙은 두 항목에는 **모든 주장 문장에 출처가 달렸고**, 서로 다른 두 문서가 인용됐다:

> 병렬 통신과 페이로드 참조를 통해 복잡한 과업을 완수하는 '코디네이션(coordination) 모드'와
> 에이전트 간 효율적인 메시지 전달을 위한 '라우팅(routing) 모드'로 구분하여 설계할 수
> 있습니다 [arXiv:2412.05449v1 / abstract].

> 단일 LLM이 모든 능력을 갖추는 대신, 과업 계획(planner), 도구 호출(caller), 결과
> 요약(summarizer)으로 능력을 분해하여 [arXiv:2401.07324v3 / abstract].

근거가 없는 두 항목은 본문에 `근거 없음`으로만 남았고 **내용이 생성되지 않았다.**

## 실행 2 — 근거가 전혀 없는 질의 (음성 케이스, GS-008)

- **run_id:** `20260915-152711-81bcd7`
- **질의:** "한국 개인정보보호법상 가명정보를 처리할 때 충족해야 하는 요건은 무엇인가?"
- **의도:** 코퍼스(arXiv AI 논문)에 근거가 전혀 없는 주제다. 모델이 **사전 지식으로 답을 지어내는지** 본다. 이 프로젝트의 1순위 제약을 직접 겨냥한 케이스다.

### 결과

조사 항목 4개 **전부 근거 없음**. 초안은 다음이 전부다.

```
## 가명정보 처리의 법적 정의 및 범위
근거 없음

## 가명정보 처리 시 준수해야 할 안전성 확보 조치
근거 없음

## 가명정보 처리의 허용 목적 및 요건
근거 없음

## 가명정보 처리 시 금지되는 행위 및 제한 사항
근거 없음
```

모델이 알고 있을 법한 주제인데도 한 문장도 지어내지 않았다. **"근거 없으면 문장을
만들지 않는다"가 프롬프트 지시가 아니라 구조로 지켜진다는 것이 확인됐다.**

## 참고 — 코퍼스 8건일 때와의 비교

세션 중간에 코퍼스가 8건이던 시점에 같은 두 질의를 돌린 기록이 있다
(run_id `20260915-150642-187606`, `20260915-152125-af5ed8`). 코퍼스를 8건 → 16건으로
늘렸을 때의 변화:

| | 8건 | 16건 |
| --- | ---: | ---: |
| 근거 있음 / 전체 항목 | 2 / 4 | 2 / 4 |
| 인용된 서로 다른 문서 | 2 | 3 |
| Writer 출력 토큰 | 479 | 663 |

**항목 커버리지는 그대로인데 인용 문서 수와 초안 분량은 늘었다.** 코퍼스가 늘어난 효과가
"못 찾던 항목을 찾게 됨"이 아니라 "이미 찾던 항목의 근거가 두터워짐"으로 나타났다.
표본이 1쌍이라 결론은 아니지만, 커버리지를 올리려면 코퍼스 양보다 **검색 방식**
(질의 재작성, top-k, 청크 전략)이 더 중요할 수 있다는 신호다.

## 두 실행에서 드러난 것

1. **Researcher가 입력 토큰의 대부분을 쓴다** — 실행 1에서 61%, 실행 2에서 94%.
   검색 후보 문서(초록)를 프롬프트에 싣기 때문이다. 다음 세션의 비용·레이턴시 실측에서
   가장 먼저 볼 지점이고, `top_k`와 스니펫 길이(`_SNIPPET_LIMIT`)가 직접적인 조절 손잡이다.

2. **벽시계 시간과 LLM 지연 합의 차이가 크다** — 실행 1은 55.60s vs 29.26s, 실행 2는
   33.93s vs 5.76s. 차이의 대부분은 **임베딩 모델 첫 로딩(수십 초, CPU)**이다. 프로세스가
   질의 1건마다 새로 뜨는 현재 실행 방식에서는 매번 이 비용을 낸다. 상주 프로세스로
   바꾸면 사라지는 비용이므로, **다음 세션의 지연 측정에서 이 둘을 반드시 분리해야 한다** —
   섞어 재면 모델이 느린 것처럼 보인다.

3. **재검색의 기대 효과가 낮다.** 네 번의 실행 모두 재검색 2회를 돌았지만 근거를 새로 찾은
   항목은 **0건**이다. 같은 인덱스에 거의 같은 검색어를 다시 던지기 때문이다. 검색어를 실제로
   바꾸는 단계(질의 재작성)가 없다는 것이 현재 구조의 한계다 (ADR-006 Risks에 기록).

4. **코퍼스가 여전히 작다 (16건).** arXiv가 이 IP를 429로 막아 5개 주제 중 2개만 수집됐다.
   실행 1의 "근거 없음" 2건이 시스템 결함인지 코퍼스 부족인지는 코퍼스를 더 늘린 뒤에야
   갈린다. 위 8건↔16건 비교는 후자 쪽에 완전한 무게를 싣지는 않는다.
