# 실행 로그 — session-08 재측정 (`PROMPT_VERSION=2026-09-16.1`)

- **날짜:** 2026-09-16
- **목적:** session-05에서 인젝션 방어가 붙으며 프롬프트가 길어졌는데 **그 비용을 재지
  않았다.** README §4는 방어 전(`2026-09-15.1`) 수치인 채 남아 있어 현재 코드와 직접
  비교할 수 없었다. 같은 방법론으로 다시 재서 **방어 전/후를 하나의 표로 비교한다.**
- **원자료:** `bench-session08-no-cache.json` / `bench-session08-cache-cold.json` /
  `bench-session08-cached.json`
- **비교 대상:** `bench-no-cache.json` / `bench-cache-cold.json` / `bench-cached.json` (session-04)

**호스트에서 쟀다 — 컨테이너가 아니다.** session-06 핸드오프는 "컨테이너가 생겼으니
컨테이너 안에서 재는 것이 맞다"고 남겼지만, 이번 측정의 목적은 **프롬프트 버전 차이를

않는다 (컨테이너는 가중치가 로컬이라 콜드 로딩부터 다르다 — 19.9s vs 10.5s).
**환경 비교는 별도 과제로 남긴다.**

`docs/governance.md` "측정 방법론"의 두 조건을 모두 지켰다: 임베딩 워밍업 분리,
`LLM_CACHE` 상태를 측정 전에 확인(`load_cache_settings().enabled == False`).

재현:

```bash
python scripts/bench_golden.py --label session08-no-cache
python scripts/bench_golden.py --label session08-cache-cold --cache --clear-cache
python scripts/bench_golden.py --label session08-cached --cache
```

## 3. 읽는 법 — 세 가지

1. **방어는 토큰으로 값을 치르고 지연으로는 치르지 않는다.** 입력이 29.5% 길어졌는데
   LLM 지연 평균은 −0.7%, 호출당 지연은 +0.6%다. 측정 잡음 범위 안이다. 이 엔드포인트에서
   지연을 지배하는 것은 입력 길이가 아니라 **출력 토큰 수**이며, 출력은 −1.1%로 거의
   그대로다. (§4.2의 노드별 지연 분해에서 Writer·Verifier가 지연을 나눠 갖는 것과 일치한다.)
2. **품질이 변하지 않았다.** 세 캐시 조건 전부 8 pass / 1 fail이고, 실패 케이스도 같은
   GS-006이다. 즉 이 방어는 **출력을 바꾸지 않으면서 토큰만 27% 더 쓴다.** "방어를 붙였더니
   품질이 떨어졌다"는 흔한 걱정이 이 측정에서는 나타나지 않았다.
3. **검색 지연 −54.7%는 방어의 효과가 아니다.** 임베딩 웜 인코딩이 88.75ms → 29.27ms로
   줄어든 데서 온다. 프롬프트는 검색 경로를 지나지 않는다. **머신 상태 차이**로 읽어야 하며,
   이 값을 개선 근거로 인용하면 안 된다.

⚠️ **n=9, 조건당 1회다.** +27.2%는 이 코퍼스·이 골든셋·이 `top_k` 기준이다.

### 노드별 — 어디가 줄었는가

| 노드 | `=2` 호출 | `=0` 호출 | `=2` 입력 | `=0` 입력 |
| --- | ---: | ---: | ---: | ---: |
| outliner | 9 | 9 | 2,525 | 2,525 |
| researcher | 54 | **34** | 83,698 | **52,079** |
| verifier | 36 | **18** | 24,730 | **12,365** |
| writer | 9 | 9 | 8,582 | **8,582** |

Verifier 호출이 정확히 절반이다(되돌림이 없으면 검증이 1회차만 돈다). **Writer의 입력
토큰이 양쪽 8,582로 완전히 같다** — Writer가 받는 근거가 같다는 독립적인 증거다.

### 그래도 기본값을 바꾸지 않은 이유

기본값을 0으로 옮기면 **되돌림 경로가 죽은 코드가 된다.** 이 루프는 ADR-006의 핵심 결정
(판정 실패를 통과시키지 않는다)을 구현하는 장치이고, 질의 재작성이 붙는 순간 값을 한다.
**"루프가 쓸모없다"가 아니라 "입력을 바꾸지 않는 루프가 쓸모없다"**이므로 고칠 곳은
파라미터가 아니라 검색어 생성이다.

⚠️ **코퍼스 16건 조건이다.** 코퍼스가 커지면 재검색이 새 문서를 물어올 여지가 생긴다.
