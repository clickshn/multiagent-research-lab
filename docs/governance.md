# 거버넌스 규칙 — multiagent-research-lab

이 문서는 **에이전트와 사람이 함께 따르는 작업 규칙**이다. `CLAUDE.md`의
`@docs/governance.md` import로 매 세션 자동 로드되며, `CLAUDE.md`와 달리
**버전 관리 대상**이다 — 규칙 변경이 커밋 이력에 남고 팀원에게도 그대로 전달된다.

규칙을 바꿀 때는 이 파일을 고친다. `CLAUDE.md`에는 개인 메모만 둔다.

## 승인 게이트

- **이미 할당된 무료 자원 호출은 승인 없이 진행 가능.** 현재 KT Cloud AI Nexus
  vLLM 엔드포인트(`VLLM_BASE`) 호출이 여기 해당한다. 추가 과금이 발생하지 않는
  기존 할당 자원이므로 헬스체크·추론 요청에 사전 승인이 필요하지 않다.
- **새로운 유료 리소스 생성은 사전 승인 필요.** 클라우드 인스턴스·관리형 서비스
  신규 생성, 유료 플랜 전환, 세션 7의 클라우드 배포 등이 해당한다.
- `terraform apply` 류의 상태 변경 명령은 실행 전 사용자 승인을 받는다. IaC 경로는
  추가로 `.claude/deploy-approved` 파일 존재를 확인하고, 없으면 실행하지 않는다.

판단이 애매하면 기준은 하나다: **이 동작이 새로운 비용이나 되돌리기 어려운 외부
상태를 만드는가.** 만든다면 승인을 받는다.

## ADR 기록

- 새 의존성 추가, 아키텍처 변경, 외부 API·서비스 선택 등 **되돌리기 비용이 있는
  결정**을 내리면 `adr-recorder` 스킬로 `docs/adr/`에 ADR을 남긴다.
- 형식과 번호 규칙은 ADR-001을 따른다 (`docs/adr/ADR-NNN-slug.md`).
- 기존 결정의 전제가 바뀌면 새 ADR로 덮지 말고, 해당 ADR에 Amendment를 추가하고
  Review Trigger 상태를 갱신한다 (ADR-002가 그 예시다).

## 시크릿 취급 — 엔드포인트 URL

**`VLLM_BASE` URL은 시크릿이다.** 이 엔드포인트는 인증을 요구하지 않고 어떤
네트워크에서든 접근 가능하므로, **URL을 아는 것이 곧 접근 권한**이다. API 키가
없을 뿐 사실상 URL이 자격증명 역할을 한다.

- `.env` 외 어디에도 평문으로 두지 않는다 — 코드, 문서, 커밋 메시지, 이슈, 테스트
  픽스처 모두 포함이다.
- 로그·에러 메시지·스크린샷·터미널 출력을 공유할 때는 마스킹한다.
  `ProviderSettings.redacted()`가 이 용도이며, 진단 출력에는 이 함수를 쓴다.
  **`redacted()`는 호스트를 가린다 (session-06에 수정).** 이전 구현은 경로만 버리고
  호스트를 그대로 남겼는데, 실제 엔드포인트의 경로는 `/v1`뿐이라 **가려지는 정보가
  없었다.** 추측 불가능한 부분은 호스트의 앞쪽 라벨이다. 지금은 공개 등록 도메인
  (`***.ktcloud.com`)과 `endpoint_fp`(URL의 sha256 앞 12자리)만 남긴다 —
  "지난 측정과 같은 엔드포인트인가"는 지문으로 답하고 URL은 드러내지 않는다.
- 공유가 필요하면 `.env.example`의 플레이스홀더 형태로만 한다.
- 커밋 전 확인 (출력이 비어 있어야 한다):

  ```bash
  git diff --cached | grep -F "$(sed -n 's/^VLLM_BASE=//p' .env)"
  ```

  URL 조각을 검사 명령에 직접 적지 않는다 — 그 자체가 평문 노출이다.
  `.env`의 실제 값을 읽어서 대조한다.

- **로컬 산출물은 위 명령으로 검사되지 않는다.** `git diff --cached`는 **커밋되는 것**만
  본다. `var/traces/`·`var/llm_cache/`는 `.gitignore` 대상이라 이 검사를 영원히 통과한다.
  그쪽은 별도로 검사한다:

  ```bash
  python scripts/scan_local_secrets.py            # 검사 (0 = 깨끗함)
  python scripts/scan_local_secrets.py --redact   # 발견 시 var/ 산출물을 마스킹 치환
  ```

  이 스크립트는 **양성 대조를 먼저 돈다** — "0건 검출"은 검사기가 고장 나도 똑같이
  나오는 결과이기 때문이다. 대조가 실패하면 스캔 결과를 버리고 종료 코드 2로 끝낸다.

상세 배경과 대응 원칙은 `README.md`의 "보안 / 운영"을 참조한다.

## 로컬 산출물 취급 — `var/traces/`, `var/llm_cache/`

- **`var/llm_cache/`는 `var/traces/`와 동일한 보존기간·접근권한 기준을 따른다.** 둘 다
  프롬프트와 **LLM 응답 본문이 평문으로 디스크에 남는** 저장소이며, 한쪽만 관리하는 것은
  의미가 없다 (ADR-007 계측, ADR-008 캐시).
- 둘 다 `.gitignore` 대상이라 커밋되지 않는다. **커밋되지 않는 것과 디스크에 없는 것은
  다르다** — 로컬 디스크·백업·화면 공유는 여전히 노출 경로다.
- 현재 넣는 데이터는 공개 arXiv 초록뿐이라 실질 위험이 낮다 (ADR-004). **이 전제가 깨지는
  순간**(사내 문서·고객 데이터 투입) 두 디렉터리는 즉시 민감 저장소가 된다.
**기준값은 환경마다 다르다. 두 개를 따로 읽는다.**

### (가) 로컬 / 개발 — 호스트 `var/`, compose named volume (session-06에 확정)

- **커밋되지 않는 로컬 개발 편의용 파일 — 필요 없어지면 수동 삭제, 별도 접근 통제 없음
  (로컬 파일시스템 권한 따름).**
  - 보존 기간: 정해진 일수 없음. 개발자가 필요 없다고 판단하면 지운다.
  - 접근 권한: 별도 통제 없음. 그 머신에 로그인할 수 있는 주체가 곧 접근 주체다.
  - 삭제: `docker compose down -v` (컨테이너 볼륨) 또는 `rm -rf var/traces var/llm_cache`
    (호스트). 컨테이너에서는 이미지가 아니라 **볼륨**에 있으므로 이미지를 지워도 남는다.

### (나) 클라우드 — EFS (session-07에 확정, ADR-015)

배포하면 `var/`는 EFS 파일시스템 1개 위의 액세스 포인트 3개(`/traces`·`/llm_cache`·`/chroma`)가
된다. **"로컬 파일시스템 권한 따름"은 여기서 성립하지 않는다** — 근거가 되는 파일시스템이
그 머신에 없다. 기준을 다시 쓴다.

- **접근 주체: IAM 역할이다.** "그 머신에 로그인할 수 있는 주체"가 아니라
  **`multiagent-research-lab-task` 태스크 역할을 맡을 수 있는 주체**가 접근 주체다.
  이 문장은 서술이 아니라 집행된다 (`infra/terraform/efs.tf`, `iam.tf`):
  - EFS 파일시스템 정책이 **태스크 역할만** `ClientMount`/`ClientWrite`로 허용하고,
    비TLS 접근을 명시적으로 거부한다.
  - 태스크 역할은 **액세스 포인트를 경유할 때만** 허용된다 — 루트 마운트로 세 디렉터리를
    한꺼번에 보는 경로를 막는다.
  - `ClientRootAccess`를 주지 않는다. 액세스 포인트가 uid/gid를 10001로 강제한다.
  - 마운트는 태스크 보안그룹에서 오는 2049 포트만 받는다.
  - ⚠️ **이 통제 위에 계정 관리자 권한이 있다.** `iam:*`을 가진 주체는 역할을 새로 만들어
    정책을 붙일 수 있다. IAM 통제는 "계정 밖"과 "계정 안의 일반 주체"를 막는 것이지
    관리자를 막지 않는다.
- **보존 기간: 정해진 일수 없음 — 로컬과 같다. 다만 삭제 책임자가 사람이다.**
  EFS에는 자동 만료가 없다. 30일 미접근 시 IA로 **내려갈 뿐 지워지지 않는다.**
  즉 **아무도 지우지 않으면 영구히 남는다** — 로컬에서 `rm -rf`를 잊는 것과 달리
  다른 사람 눈에 띄지도 않는다. 필요 없어지면 지운다는 원칙은 같지만, **지울 사람을
  정해 두지 않으면 지워지지 않는다**는 점이 로컬과 다르다.
- **삭제:** `terraform destroy` (EFS째 삭제, **데이터가 함께 사라진다**) 또는 태스크를
  띄워 마운트한 상태에서 해당 디렉터리를 비운다. ⚠️ **ECR 이미지를 지워도, 태스크 정의를
  지워도 EFS는 남는다** — 로컬에서 "이미지를 지워도 볼륨은 남는다"와 같은 함정이다.
- **CloudWatch Logs는 별개다.** 태스크 stdout/stderr는 EFS가 아니라 로그 그룹에 가고
  보존 기간이 **14일로 설정돼 있다**(`var.log_retention_days`). 여기에도 질의 원문과 초안
  본문이 섞여 들어가므로 "덜 민감"할 뿐 무해하지 않다.

### 두 환경에 공통으로 걸리는 것

- ⚠️ **이 기준 전체가 ADR-004의 "공개 arXiv 초록만 넣는다"에 의존한다.** 위 전제가 깨지는
  순간(사내 문서·고객 데이터 투입) 이 기준은 **즉시 무효**이며, 보존 기간·접근 주체·
  삭제 책임자를 정하는 것이 그 투입의 선행 조건이 된다. 감사 로그 요구가 규제성이라
  나중에 붙이기 어렵다 — **실데이터 투입 전에** 다시 정해야 한다.
  클라우드로 옮겼다고 이 조건이 해소된 것이 아니다. **노출 경로가 로컬 디스크에서
  AWS 계정으로 바뀌었을 뿐이고, EFS 암호화는 AWS 관리 키라 계정 내부를 막지 않는다.**
- **Langfuse는 클라우드에 없다** (ADR-016). 클라우드 실행의 계측은 EFS의 JSONL과
  CloudWatch Logs뿐이다. 로컬 Langfuse에 쌓인 것은 (가) 기준을 따른다.

## 측정 방법론

- **지연·비용을 측정하기 전에 `LLM_CACHE` 환경변수 상태를 확인한다.** 켜진 채로 측정하면
  파이프라인 성능이 아니라 캐시 적중률을 재게 된다 (ADR-008). 캐시 기본값이 꺼짐인 이유이고,
  `scripts/bench_golden.py`가 `cache_enabled`를 결과 JSON에 기록하는 이유다.
- 임베딩 콜드 로딩(19~30s)은 질의 지연이 아니다. 측정 전 워밍업해서 분리한다.

## 코드 규칙

- **엔드포인트·모델 값을 코드에 고정하지 않는다.** `.env`의 `VLLM_BASE` /
  `VLLM_MODEL`을 읽어 프로바이더 계층(`src/providers/`)에서만 참조한다.
  다른 모듈이 이 환경변수를 직접 읽으면 엔드포인트 교체가 코드 변경이 된다 (ADR-003).
- **모델 고정 원칙.** 모델은 고정하고 오케스트레이션 구조·검증 루프·컨텍스트 관리는
  하네스로 분리한다. 성능 변화의 원인(모델 vs 하네스)을 구분하기 위함이다 (ADR-002).
- 경로별 세부 컨벤션은 `.claude/rules/` 참고 (orchestrator / security / iac).
